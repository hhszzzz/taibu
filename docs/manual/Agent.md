# Agent 使用与实现边界

## 使用方式

在聊天中启用 Agent，由后台 worker 连续执行推理与工具调用。平台模型按实际用量计费，BYOK 使用用户提供的模型连接，不计费，见「计费与自定义模型」。

Agent 可以调用排盘、命理拓展、知识库、历史对话、受控联网工具，以及管理员或用户接入的外部 MCP 服务和技能。计算和格式化复用 `taibu-core`，方法随 Core 维护；支持范围与算法参数见 Core 的 README 和 `ALGORITHM_RULES.md`。

详查工具与八字合盘（`bazi_hepan`）直接引用本会话排过的命盘（`artifact:成果ID`）或用户已存的命盘（如 `bazi_chart:ID`），出生或起卦参数由服务端从成果或记录重建，模型不转抄；没有出生时间的记录只重建年、月、日三柱，不补时柱，也不给时柱推出的命宫、小运等内容。每次执行与缓存重放都重新核对命盘归属。合盘结果在工作区「推演」中把两人八柱排成一条，两盘之间的干支关系画成连线，再按日柱（领以日主互见）、年柱（领以生肖与年命纳音）、其余三组逐条列出，指着一条关系时连线与两端的字亮起；只陈述事实、不打分。

方法分三类：体系默认方法、流派方法与技法。技法在遇到其所述情形时与体系方法同用，不单独作为协作成员的分工。出生时辰未知时按「推理时柱」（`birth-hour`）先推时辰再分析：`bazi_hour_candidates` 列出出生当天各时辰的时柱事实与给定前事年份的引动（交节、子时换日或真太阳时跨日时同一时辰拆开），只陈述事实、不排序；模型据此向用户核对六亲与前事，剩两三个候选时用紫微交叉，经用户确认后才以该候选的出生时分正式排盘，用户答不上来时只排三柱。论断依赖拿不准的取舍（旺衰、格局、时辰交界）时按「验证前事」（`past-events`）先请用户核对两三件往事，再论将来。候选时辰在工作区「推演」中逐个列出。

模型菜单可配置代码模式与计划模式，默认关闭，对下一任务生效。代码模式在沙箱中组合调用受控工具，不能直接调用模型；计划模式允许先研究，提交计划并获用户批准后才可写入长期记忆、归档或派出子分析。计划正文按 Markdown 显示，等待批准时在任务过程中自动展开；批准、修改意见与历次修订都留在工作区的分析计划页。低频工具通过工具搜索按需加载。管理员可在「功能开关 → Agent 工具范围」关闭其中任一模式：关闭后输入框不再提供该选项，已保存的开关会失效，服务端也会拒绝新建任务和运行中任务的对应工具。关闭时若任务正等待计划批准，用户的回复不再算作批准，受计划审批保护的工具保持禁止，任务整理已完成的研究后收尾，工作区标注「计划模式已关闭」。

浏览器随请求带上所在的 IANA 时区（缺失或无效时按 `Asia/Shanghai`）。普通对话与 Agent 的每条新消息开头写入服务端收到时的「发送时间」（本地时间、星期与 UTC 偏移），任务中途插入、排队和回答问题的消息，以及交给协作成员和后台子分析的任务同样写入；系统提示词不含时间，不随分钟变化，便于模型服务缓存。占当下起卦起局、今天、今年与年龄都以最新一条的发送时间为准。只走人格提示词的一次性分析（如面相/手相照片解读）仍在系统提示词开头写北京时间；各占术结果页不再页内解读，统一由 AI 对话处理。

多模型协作通过 `parallel_analysis` 分工后汇总；`background_agent` 提供可并行推进、自动回报并在同一对话中接续的常驻子分析，支持追加任务、停止与解散。成员与子分析按角色工作，工具、指令与模型由角色决定，见「协作成员与角色」。

## 引用

在助手回答里选中文字会浮出「引用」按钮（手机长按选择同样可用），消息操作行另有「引用整条」。引用进入输入框上方的引用条：最多 3 段，每段最多 1000 字，超出时截取，每段可单独移除；切换对话时清空。

发送后引用随用户消息写入 `quotes`（`{ messageId, text }`），在用户气泡上方显示为引用卡。普通对话与 Agent 共用同一个序列化函数：引用块写在用户消息前面，声明为参考资料而不是指令；Agent 的 pi 历史与普通对话的提示词因此看到相同内容。分享页只读显示引用卡的文字，不带来源消息 id。引用只对本次发送生效，任务进行中不能附带引用。

## 定时任务

侧边栏「定时任务」进入 `/scheduled`。每个任务绑定一个固定对话：到点后以任务所有者的身份把这一轮追加进去，`origin` 记为 `schedule`，之后的回答、通知与普通 Agent 任务一致。任务的对话在「最近使用」里带时钟标记。

- 频率：每天、每周几、每月几号或固定间隔（1–24 小时，按本地执行时刻循环），都带 `HH:mm` 与时区。下次运行时间在数据库里按当地日历计算，跨时区、夏令时和月末（如 31 号在二月按月末）都成立。
- 错过的运行：服务中断后只补最近一次，且只在其计划时间两小时内；更早的记为 `skipped / missed`。上一次还在运行时，本次记为 `skipped / previous_running`。
- 跳过与通知：余额不足（`insufficient_balance`）、模型未定价或已下线、功能关闭时记为 `skipped` 并写站内通知；绑定的对话被删除时任务暂停并提示重建。任务可设置完成或失败时是否通知；暂停的任务仍可「立即运行」，但同样检查余额、模型与功能开关。
- 数量：每人默认 20 个（可设 0–100），管理员在「设置 → Agent 扩展 → 定时任务额度」调整。上限由创建与启用的数据库函数自己读取，请求里没有可传的额度，浏览器不能给自己放宽。管理员调低上限后，超出的任务在下一分钟自动暂停，保留创建最早的几个；之后需手动恢复其余任务。
- 模型可选平台模型，或 Key 保存在本站的自定义模型；Key 只在浏览器里的连接不能用，定时运行时没有浏览器。平台模型按 Agent 任务的规则按用量计费，自定义模型不计费。运行时模型已删除、Key 不再保存在本站或管理员关闭了自定义模型，本次记为 `skipped / model_unavailable`，通知写明原因。运行历史列出每次的计划时间、状态、跳过原因或错误，并可打开绑定对话。管理员在「设置 → 日志 → 定时任务」查看全站的运行记录，按状态、用户邮箱与时间筛选，详情里有关联的 Agent 任务与它的费用。
- 内置模板「每日早报」：今天黄历宜忌，加上绑定命盘（默认命盘或指定命盘）的当日运势；时间、时区和提示词都可改。早报不再有独立订阅：从旧版本升级时，迁移 `0001` 删除原来的早报设置与提醒订阅，不会自动转成定时任务，需要的用户用这个模板重新创建；已生成的早报对话保留为普通对话。

## 可视化

普通对话、Agent 回答、照片解读与分享页共用同一套可视化卡片：标题、全屏、主题跟随，出错时可展开数据或源码。当前版本全局暂停图表输出：提示词不再要求模型生成 `` ```chart `` 或 `` ```visual ``，八字命盘、解梦与命盘提及都不会自动附带图表；历史消息里的图表与可视化卡片照常渲染，设置页的可视化偏好暂时只影响文字分析中的关注维度。恢复输出时改 `src/lib/visualization/output-switch.ts` 的开关。

- 内置图表仍是 15 种结构化模板（运势雷达、大运趋势、五行能量、运势日历、合婚仪表、人生时间轴等），JSON 结构与选择规则写在同一条可视化提示里；各占术按数据源限定可用的类型。历史消息里的 `` ```chart `` 照原样渲染；渲染器兼容数组式五行、简化的大运数据等模型常见的变体。
- 图表块渲染前先校验：类型必须是内置模板，且该模板的核心字段齐全。JSON 无效、类型未知或字段缺失的块不画半张图，正文位置留一行「图表暂不可用，文字解读仍保留」，每条消息提示一次；渲染时抛错按同样方式收起整张卡。五行图只在数据给出喜用神时标注，不再从最旺、最弱的五行推断。
- `` ```visual `` 在 `sandbox="allow-scripts"` 的 srcdoc iframe 中渲染：不给 `allow-same-origin`，内容读不到站点 Cookie 与存储；外壳 CSP 禁止联网与外部资源，`fetch` 与 XHR 都会被拦截。首行可写 `<!-- 标题 -->` 作为卡片标题，正文上限 64 KB；超过上限或围栏没有闭合时只显示说明与源码。
- 生成过程中只显示占位，消息完成后才渲染，避免执行半截脚本；主题切换会同步到沙箱。导出 HTML 时脚本被禁用，`visual` 导出为静态说明加可折叠源码；Markdown 导出保留原始代码块。

## 生图

「生图」是文生图，只做文字描述生成，不接受参考图编辑。管理员在「AI 服务 → 模型」添加用途为「生图」的模型，沿用现有网关与来源故障转移，并填写每张图的单价（美元，0 为免费，留空为未定价、不提供）。生图模型不出现在对话模型菜单里。

- 输入框：有已定价的生图模型或自己的生图模型时，工具栏出现「生图」按钮。开启后发送直接生成图片，不经过对话模型；有多个生图模型时可选模型（自己的标「自定义」，所选模型按账户记在本机，Agent 的生图工具也用它），可选尺寸（方形 1024×1024、横向 1536×1024、竖向 1024×1536、宽幅 1792×1024、长幅 1024×1792）与张数（1–4），并显示本次费用。`+` 菜单的「优化提示词」沿用 `/api/chat/enhance`。生成成功后用户消息与助手消息一起写入当前对话；失败不留下空对话。空对话里有一句生图示例。
- 自定义生图模型：请求 `{地址}/images/generations`，每张一个请求，优先要 base64。Key 保存在本站的由 `/api/images/generate`（`model` 传 `byok:` 引用）代发；Key 只在浏览器里的由浏览器直接请求，再把图片交给 `POST /api/images/upload` 保存。上传校验登录、限流、模型归属与用途、对话归属、1–4 张、单张 10 MB，按文件内容识别静态 PNG、JPEG、WebP 并读出实际宽高。两种方式的图片都记在该模型的 `byok:` 引用下，不计费。浏览器读不到服务商返回的图片地址（跨域）时，错误提示建议打开「保存到本站」。
- Agent 工具：`generate_image({ prompt, size?, n? })` 用会员在生图模式选的模型（没选时用第一个已定价的平台生图模型），有可用的生图模型时才注册；自己的生图模型由本站代发，Key 来自本站保存或任务暂存，不计费。归入「生图」工具范围，可在后台关闭；协作成员与后台子分析永远拿不到。单次任务累计最多生成 4 张，超出的调用被拒绝。用户明确要求图片时才应调用，工具不会主动生图。
- 计费：每次请求按「张数 × 单价」预扣，不允许欠费；全部来源失败时整笔退还，某来源只返回部分图片时只退未交付的部分。余额不足返回 `INSUFFICIENT_BALANCE`，不调用模型。免费生图模型与自定义生图模型按实际出图张数记 $0 流水，后者标 `byok`。
- 存储与读取：图片写入对象存储桶 `generated-images`（`FILE_STORAGE_ROOT` 下，与附件同卷），元数据记入 `generated_images`，含用户、对话、任务与消息、模型、提示词、尺寸、对象路径、类型、字节数与 SHA-256。读取走 `/api/images/[id]`：仅本人可读；公开分享页在图片地址上带分享令牌，服务端核对令牌所属对话后才返回该对话的图片。每次读取都校验大小与摘要，响应带 `Cache-Control: private, no-store`、`X-Content-Type-Options: nosniff` 与沙箱 CSP。
- 清理：删除对话或账号会随外键级联删掉图片记录，对象由 `agent-attachments-cleanup` 定时任务清理：把桶里的对象与 `generated_images` 比对，只删除 24 小时前且表里没有对应记录的对象（上传中途失败留下的字节同样由此回收），每次最多 200 个。
- 失败转移：同一模型的来源按顺序尝试；单个来源报错、超时或被中止时换下一个，全部失败才报错。内容安全依赖上游审核。

## 任务状态与恢复

| 状态 | 行为 |
| --- | --- |
| `queued` | 等待 worker 取得租约 |
| `running` | 执行当前 checkpoint 和待处理命令 |
| `awaiting_input` | 等待用户回答，回复后继续 |
| `cancelling` | 已请求停止，等待执行与结算收敛 |
| `completed` / `failed` / `cancelled` | 终态，保留任务与可见历史 |

当前运行引擎为 `pi-durable/1.5.0`。只有匹配当前引擎的 worker 可以接管任务；SQL 定义刷新时，会结束当前引擎无法执行的未完成 checkpoint，并通过既有结算函数处理退款与状态，保留已完成历史和产物。

模型请求走 pi-ai 自带的 Chat Completions 传输（`src/lib/agent/pi-stream.server.ts`）：网关流出的推理（`reasoning_content` 及同类字段）存为思考，并随助手消息一起回传，模型在工具调用之间接着自己的思考往下做，不必每一步从头推理。系统提示要求每批工具调用前先用一句话说明目的。一次回复既没有正文也没有工具调用，或者只说了下一步要做什么却没有调用工具时，会带一段提醒（追加在系统提示末尾）再请求一次，第二次的输出接在同一条回复里；再次没有输出时任务以明确原因失败。思考用完单次输出上限而没有回答时不再重试，直接提示调低思考等级。

模型按管理员在设置中心「AI 服务」里的配置调用：上下文窗口决定压缩阈值；思考只用模型勾选过的等级，未勾选的等级按最接近的一档执行；开关与等级都写进请求体的 `reasoning_effort`，普通对话与 Agent 写法一致，自定义参数不能覆盖。来源按列表顺序故障转移，密钥在请求时才解开。

模型请求的所有来源都因过载、限流、网络或 5xx 失败时，任务持久休眠后重试两次（3 秒、6 秒），休眠期间 worker 可以停止或交接。回答失败时，用户在此期间插入的消息会接着开始下一轮回答，不会丢失。某一步连续 5 次让 worker 意外中断（未提交新状态）时，Pi 不再重试它：工具调用以错误结果结束，模型据此继续作答；模型请求则结束本轮回答，任务以失败结束并提示重新发起；压缩按压缩失败处理。模型请求进行中 worker 意外退出时，这次请求按失败计入上面的两次重试，不会在接管后原样重发；重试用完后同样以失败结束。协作成员的模型按各自的上下文窗口决定压缩阈值。

任务 checkpoint、命令、工具调用收据和事件在 PostgreSQL 持久化。租约与递增 fence 拒绝旧 worker 的迟到写入。相同请求与工具提交重试保持幂等；用户追加、编辑排队消息和回答问题继续复用原任务。

停止请求不会回滚已经完成的外部操作，也不退回已经发生的模型用量。

## 计费与自定义模型

- 准入：提交时模型须已定价，否则返回 403 `MODEL_UNPRICED`；付费模型还要求可用额度（订阅剩余加钱包）大于 0，否则返回 402 `INSUFFICIENT_BALANCE`，都不创建任务。平台模型任务记为 `billing = 'metered'`。
- 按用量：每次模型请求前再确认余额为正，结束后立即按上游返回的用量入账（输入、缓存读、缓存写、输出），每次一条 `billing_ledger` 流水，引用该任务；上游没报用量（中断、出错）时按提示词与已产出内容估算，流水标 `estimated`。子代理、协作成员、后台子分析与压缩上下文的请求都在这里计费。按会员在钱包页选的顺序扣订阅额度或余额（先订阅时窗口从短到长）；最后一次请求允许把钱包扣成小额负数，下次充值抵扣。
- 余额耗尽：下一次模型请求前任务以「余额不足，任务已停止；充值、兑换或订阅后可以继续」结束；已完成的请求照常计费。
- 免费模型（单价全为 0）不查余额，每次请求照样记一条 $0 流水，供用量日志统计。
- 自定义模型（BYOK）：主模型、协作成员与生图模型都可以是会员自己的模型（`byok:` 引用），可与平台模型混用。只用自己的模型的任务记为 `exempt`，不查余额；有平台模型参与时记为 `metered`，平台模型照常准入与计费，自己的模型每次请求记 $0 流水。Key 保存在本站的由 worker 解密使用；Key 只在浏览器里的，提交时浏览器按连接附上，服务端校验后加密暂存，任务结束即删除。提交时模型不存在、用途不符或缺 Key 都直接拒绝，不创建任务；运行中模型被删除或 Key 打不开时，任务以「自定义模型不可用」结束。自己的模型请求失败时，任务结束语是服务商返回的状态码与原文。

## 权限与凭据

- 用户只能访问自己的任务、对话、知识库和附件。管理员任务日志用于排查运行状态，不授予读取他人聊天正文的权限。
- 模型和工具权限在服务端校验；浏览器字段不能授予系统身份或改变任务所有者。
- 后台执行绑定任务所有者和有效租约，缺少上下文时失败。
- 自定义模型的 Key 用 `AGENT_CREDENTIAL_ENCRYPTION_KEY` 派生的子密钥加密：任务暂存的绑定所有者、任务与连接，终态清除；保存到本站的绑定所有者、连接与域名，换域名后须重填。密钥必须由同一部署的 Web 与 worker 共享。
- 网关密钥由同一把密钥派生的子密钥加密存入数据库，并绑定到所在网关；模型目录缓存里只有密文。更换该密钥后需要重新填写网关密钥。
- 联网请求通过现有安全访问层，禁止访问私网和其他被拒绝的目的地址。

管理员可以在设置中心「功能开关」分别关闭用户功能模块和 Agent 工具范围。模块开关会同时阻止对应的 Agent 排盘、详查和资料读取；Agent 工具范围还可以在不关闭用户页面的情况下收紧八字、知识库、联网/MCP、技能、长期记忆、档案写入、协作、代码模式和计划模式等能力。工具定义会保留在 Agent 上下文中，服务端在每次调用（包括缓存重放和脚本调用）前重新读取策略，关闭时向 Agent 返回可修正的权限错误。代码模式与计划模式还会从输入框移除、复位已保存的开关，并阻止新建任务启用对应模式。模块状态使用 `feature_disabled:<id>` 保存，Agent 范围使用 `agent_tool_disabled:<scope>` 保存，均由管理员 API 写入 `app_settings`。

管理员可在设置中心的「日志 → Agent 任务」按任务、对话或用户 ID 排查；地址带 `?q=<ID>` 时直接查找，用量日志与定时任务记录里的「查看任务」都跳到这里，任务详情附这次任务的模型调用费用。任务树从持久化日志重建，结束后仍可查看；该接口裁剪聊天正文、工具结果和私有文档，只提供排障需要的运行信息。「性能」子页按模型查看近 1 / 7 / 30 天的运行指标，见「运行性能与遥测」。

## 外部服务（MCP）

管理员在设置中心「Agent 扩展 → MCP 服务」接入平台服务，对所有用户开放；用户在「设置 → 扩展 → 连接器」添加只对自己生效的连接器。两者都是 Streamable HTTP 的公开 HTTPS 地址，只在开启联网、且「联网/MCP」工具范围开启的任务中加载。

- 提供方式：`direct` 随每次请求提供；`deferred` 经 `tool_search` 检索后加载；`codemode` 只能在代码模式脚本中调用；`hidden` 不注册工具，只供联网搜索与读网页的路由使用。用户连接器只能选前两种，不参与联网路由，每台最多注册 50 个工具（平台服务 200 个）。
- 工具名为 `mcp__<标识>__<工具名>`，非法字符替换为 `_`，超过 64 字符或重名时加短哈希；用户连接器与平台服务同标识时前缀加哈希，跨任务保持不变。
- 每个工具可设置启用、中文标题、检索关键词与「调用前征求用户同意」。需同意的工具调用前向用户提问，拒绝时返回工具错误；代码模式脚本不能调用它们。
- 输入框下方的「外部工具」选择按任务决定同意策略：**自动**（默认，只问标了「征求同意」的工具）、**手动**（每个外部工具调用前都问）、**全部允许**（直接调用，不再询问）。脚本里不能等用户回答，所以「手动」下代码模式不注册外部工具。
- 每次调用前重新读取服务：停用、删除或管理员关闭个人连接器后，进行中的任务下一次调用即被拒绝。一次调用只发送一次，任务中断后不自动重发。
- 服务自带的说明（instructions）只在设置页展示，不进入系统提示；系统提示只列服务名称与管理员或用户写的用途说明。工具描述标明来源，返回内容按外部资料处理，超出字数上限时保留首尾、省略中间，图片只给模型占位。
- 任务开始时连不上的服务被跳过：系统提示只列出其名称，上下文卡显示「未连上」的个数。平台服务的失败记到管理页；用户连接器的原因由用户在连接器页测试连接查看。
- 密钥（请求头或查询参数）以 `AGENT_CREDENTIAL_ENCRYPTION_KEY` 经 HKDF 派生的独立密钥做 AES-256-GCM 加密，附加数据绑定归属、服务与字段名；只写不回显，错误信息与日志先清除密钥原文。更换该主密钥后需重新填写全部 MCP 密钥。连接复用进程级连接池，地址校验与拒绝重定向沿用安全访问层。

「Agent 扩展 → 用户扩展」决定是否允许用户添加连接器与技能、每人可加几个（默认连接器 10 个、技能 30 个，最多可设 50、100），保存在 `app_settings` 的 `agent_extensions_policy`。关闭后已添加的保留但不再使用；调低数量后超出的按排序靠前的生效。

服务存于 `agent_mcp_servers`：`owner_id` 为空是平台服务，只有管理员可读写；非空是用户连接器，只有本人可读写。worker 以管理员身份读取全部，但只能写平台服务，他人无法把用户保存的密钥指向别的地址。

## 联网搜索与读网页

Agent 的 `web_search`、`web_fetch` 与普通对话的联网搜索都路由到管理员接入、填了「搜索工具」或「读网页工具」的平台 MCP 服务；用户连接器不参与。没有这样的服务时全站不提供联网搜索，输入框的联网开关会说明「当前环境未配置联网搜索」。

- 选择与转移：只用已启用的服务，按路由优先级（数字小的先）、排序、标识依次尝试；出错、超时、返回错误结果或没有结果时转下一个。联网搜索对所有用户开放，也可以与上传的文件同时使用。
- 熔断：同一进程内，一个服务连续失败 3 次后暂停 1 分钟，原因写到管理页该服务的状态上，恢复应答后清除；全部服务都在暂停时直接报告暂不可用。读网页时因网页本身读不到而返回的错误结果只转下一个服务，不计入失败。
- 参数按工具列出的输入结构生成：搜索词写入 `query`（或该工具唯一的必填文字参数），条数写入 `numResults`、`max_results` 等并受其上下限约束；网址写入 `urls` 或 `url`，正文长度写入 `maxCharacters` 等。工具名以测试连接列出的为准，`-` 与 `_` 的差别会被忽略（如 Tavily 托管版的 `tavily-search`）。
- 结果自动识别：先读 `structuredContent.results`，再读 Exa、Tavily 这类逐条写 `Title:` / `URL:` 的文本（Exa 读网页的 `# 标题` 也算），最后读 Markdown 链接；只保留 http(s) 地址，同一地址只留一条。搜索每次 5 条（最多 10），每条摘要不超过 1500 字；读网页取请求的那一页（重定向后取服务读到的页），正文默认不超过 8000 字。结果先清除该服务的密钥再交给模型。
- 引用：`web_fetch` 的结果与搜索结果一样编号，进入回答依据与来源卡片。读网页会把网址发给外部服务，工具说明要求模型不读取含个人信息或密钥的地址；带账号密码的网址直接拒绝。
- 接入：管理页的 Exa 模板使用 `https://mcp.exa.ai/mcp`，密钥请求头 `x-api-key`，工具 `web_search_exa` / `web_fetch_exa`；Tavily 模板使用 `https://mcp.tavily.com/mcp/`，密钥请求头 `authorization`，值为 `Bearer tvly-…`，工具 `tavily_search` / `tavily_extract`。两者默认「不注册（仅联网路由）」，模型只看到 `web_search` / `web_fetch`，不会同时看到原始工具。

不再读取 `TAVILY_API_KEY`：升级后在管理页接入搜索服务之前，联网搜索不可用。

## 技能

技能沿用 pi 的 SKILL.md（Agent Skills 格式）：开头的 YAML frontmatter 写 `name`（小写字母、数字与单个连字符，最多 64 个字符）和 `description`（最多 1024 字），之后是做法正文；写了 `disable-model-invocation: true` 的技能不告诉模型，只能由用户调用。pi 从磁盘找技能，再让模型用文件工具打开；任务没有磁盘，所以技能存在数据库里，由 `load_skill` 与 `read_skill_file` 读取，其余照 pi 的格式。

- 添加：管理员在「Agent 扩展 → 技能」添加平台技能；用户在「设置 → 扩展 → 技能」添加只对自己生效的技能，个数受上面的用户扩展策略约束。两处都可以粘贴 SKILL.md，或上传技能文件夹（保留相对路径，跳过隐藏文件）。SKILL.md 最大 128 KB；附属文件只存 UTF-8 文本、从不执行，最多 64 个，单个 1 MB、合计 8 MB。SKILL.md 或附属文件有改动时版本号加一。
- 同名：平台技能优先。用户不能新建或改名为平台已有的名称；管理员后来添加同名平台技能时，用户的那个不再生效，列表标出「被平台同名技能覆盖」。
- 任务中：任务开始时，系统提示的 `taibu_skills` 段先列出本例工具能解读的方法（方法 id、名称、适用、对应工具与解读通则），再按 pi 的 `<available_skills>` 列出允许模型调用的技能名称与说明——已启用的平台技能，加上用户自己已启用的、按排序取到策略允许的个数。模型用 `load_skill` 读入正文（填方法 id，或刚调用的 Core 工具名取该体系的默认方法），用 `read_skill_file` 按段读取附属文件（每次 8000 字）。两个工具每次调用都重新查找技能，停用、删除或关闭「技能」工具范围后立即生效。协作成员与后台子分析只有角色授予「技能」时才有这两个工具和该段；角色还可以预载平台技能。
- 输入框：`/skill:名称 要求` 把该技能的正文放进这一轮（展开格式与 pi 相同），对话里仍显示用户原文；斜杠菜单列出可用技能，包括只能由用户调用的；内置方法不进菜单（`/skill:bazi` 仍可用）。技能不可用时发送即报错，不创建任务、不计费。发往进行中任务的 `/skill:` 消息由 worker 送达时展开；重建上下文时，历史里的 `/skill:` 消息再展开一次。
- 方法就是内置技能：15 个方法随发布版本编译（`skills/taibu-divination/methods` 经 `pnpm build:methods` 生成到 `taibu-core`），任务里用同一个 `load_skill` 加载、同一段 `taibu_skills` 目录列出，方法里写的工具一定与当前 Core 一致，管理员不能编辑。技能开关只管数据库里的技能：关掉后内置方法仍可加载，任务照常运行；技能目录读不到时任务也保留内置方法。方法的加载结果带 `details.method`，工作区据此开方法页。
- 边界：技能只是做法说明，不改变任务权限与工具范围，系统提示也写明它不能凌驾于系统指令之上。

技能存于 `agent_skills`（`owner_id` 为空是平台技能）与 `agent_skill_files`，权限同连接器：平台技能只有管理员可写，用户技能只有本人可读写，worker 以管理员身份读取全部。平台技能经共享缓存在 web 与 worker 之间同步，管理员保存后立即失效。

## 协作成员与角色

pi-durable 把成员会话建成主任务的副本，再用 `AgentChange` 收窄它的工具、指令与模型；pi 桌面版的子智能体按「继承父级工具再禁用一部分」或「只给列出的工具」定义。角色照此实现，只补 pi 没有的部分：角色存在数据库里、在管理页编辑，工具可以按工具族授予。

- 内置角色：`specialist`（体系专家，用任务 `system` 所指方法的 Core 工具，即原来的成员）、`researcher`（研究员：联网、知识库与技能）、`verifier`（复核员：全部 Core 工具、用户资料、读网页与知识库，核对数据与引用，不写入）。内置角色只能启停，体系专家不能停用；要让成员用 MCP 服务，新建自定义角色。
- 自定义角色：管理员在「Agent 扩展 → 角色」添加。标识以小写字母开头，2–32 个小写字母、数字或连字符，保存后不能改；名称最多 12 字；说明最多 300 字，是主任务挑选成员时读的；指令最多 8000 字，附在固定规则之后，不能放宽它们。另可设工具、预载技能、模型与推理档位、用途（协作成员 / 后台子分析）、排序与启用。
- 工具：不继承时只有「允许」的工具，继承时是主任务的全部工具；「禁止」总是生效。两者可以写工具名，或工具族 `system`（所给体系）、`core`、`core:<体系>`、`data`（用户资料）、`web`（`web_search`、`web_fetch`）、`knowledge`、`skills`（`load_skill` 与 `read_skill_file`）、`mcp:<平台服务标识>`。授予 Core 工具时自动带上 `load_skill`（方法是内置技能），除非禁止。成员一开始就拿到全部工具，没有工具搜索；系统提示只列它拿到工具的 MCP 服务。需征求用户同意的和只供脚本调用的 MCP 工具不给成员；`mcp:` 只指平台服务，用户自己的连接器只随「继承」给出。
- 固定不给成员：`ask_user`、`todo_write`、`submit_plan`、`parallel_analysis`、`background_agent`、`remember_user_fact`、`record_user_event`、`propose_archive_entry`、`inspect_chart`、`focus_chart`、`tool_search`、`codemode`、`generate_image`，管理页拒绝把它们写进「允许」。成员调用没给它的工具时，pi 直接返回该工具不可用，不执行；给了的工具每次调用仍校验联网开关、工具范围与 MCP 服务状态。
- 预载技能：最多 4 个平台技能，只载入已启用的，正文随成员指令一起提供，合计不超过 24000 字，超出的不载入；角色同时授予「技能」时一并列出附属文件。
- 模型：角色指定了模型且该模型仍已定价时，成员用它，推理档位按角色设置（不填为模型默认）；否则用协作设置里给这位成员选的模型，再否则用主模型。角色模型只代替平台模型：选了自己模型的成员仍用它，只用自己的模型的任务不用角色模型。
- 来源：成员检索与外部服务的结果不编号，成员在回报里写明来源标题与网址；编号只属于主任务自己的搜索结果。
- 用户：「设置 → 个性化 → 多模型协作」为每位成员选角色，默认体系专家；角色指定了模型时会说明它在可用时代替所选模型。提交时角色已停用即报错，不创建任务；主任务派这位成员时不能改用其他角色。
- 主任务：两个工具的说明列出本任务可用的角色及其能用的工具族；系统提示要求默认自己完成，只把相互独立的子问题分出去，不让成员互相辩论，复核最多一轮，成员之间不传话。
- 进度：协作成员与后台子分析的进度订阅各自会话的 `Conversation.watch()`，不再定时轮询；成员卡与子分析卡显示角色。
- 后台子分析记得自己的角色，之后的提问里按原角色重建；角色停用后不再重建，也不再列给主任务。
- 存储：自定义角色存于 `agent_profiles`，只有管理员可读写；内置角色的停用记录存于 `app_settings` 的 `agent_builtin_profiles`。两者经共享缓存在 web 与 worker 之间同步，管理员保存后立即失效；任务开始时取定可用的角色，之后的改动从下一个任务起生效。
- 未做：pi 桌面版已去掉子智能体的轮数上限（`max_turns`），pi-durable 也没有按会话的轮数上限，所以角色不设轮数；成员模型不另设回退，模型请求本身已在各来源之间转移。

## 运行性能与遥测

每个任务结束（完成、失败或停止）时，worker 把这一次运行的指标写进 `agent_run_metrics`，由 `@earendil-works/pi-telemetry` 的 `TelemetryContext` 适配 pi-durable 的无内容遥测；等待用户回答的中间状态不写，恢复后到真正结束时再写。运行指标只收白名单字段：

- 模型、终态、该次执行的开始与结束、排队耗时（首次领取前的等待）与总耗时
- 首字延迟：从执行开始到模型流出第一段内容；每轮 token（输入、输出、缓存读取、缓存写入、合计）由 `pi-stream.server.ts` 记入
- 生成、工具、压缩的次数与累计耗时（Pi 的 `pi.durable.phase.duration` 指标）
- 重试（同一生成任务第 2 次及以后的 attempt）、故障与中断（Pi 的 `pi.durable.reports`，`task_interrupted` 记为中断：某一步被崩溃反复打断后 Pi 结束了它）
- 阶段时间线：`pi.durable.phase`、输入提交 `pi.durable.submit` 与提交结算 `pi.durable.submission` 的任务名、阶段、attempt、结果、状态与相对耗时，最多保留 500 条

消息正文、工具参数、工具结果、系统提示与密钥都不读取、不写库。指标只管理员可读；没有遥测的旧任务不显示指标。

「日志 → Agent 任务 → 性能」按模型给出近 1 / 7 / 30 天的总耗时与首字延迟 P50/P95、工具耗时占比、失败率与中断率，并列出最近的运行；点开一次运行看它的阶段时间线。数据保留 30 天，由 `agent-retention` 定时任务清理（与事件、提交日志和 worker 心跳同一次执行）。

## 提示缓存亲和

同一对话的多轮请求可以命中模型服务的提示缓存，减少重复计费并降低首字延迟。提示缓存亲和**默认开启**，所有模型都会在请求里带上缓存键。网关不认识 `prompt_cache_key`、会因此返回 400 时，在该模型「自定义请求参数（JSON）」里写 `{"promptCacheKey": false}` 单独关闭；显式 `false` 是唯一的关闭方式。

- 普通对话取浏览器提交的对话 ID，Agent 任务取任务的对话 ID；两者都与所属用户一起计算 SHA-256 摘要，以 `taibu-` 前缀加 40 位十六进制发送为 `prompt_cache_key`。上游拿不到对话 ID 与用户 ID 本身，两个用户也不会落进同一个缓存分区；浏览器提交的对话 ID 只做长度校验，摘要里绑定用户正是为了让请求无法指向他人的分区。
- 同一对话的每次请求（包括失败重试和提醒后的再次请求）使用同一个键，不同对话的键不同。
- 效果在「日志 → Agent 任务 → 性能」的缓存读取 token 中核对：同一对话的多轮 Agent 运行应出现缓存读取；普通对话的缓存用量由网关侧记录。

## Agent 测评

「AI 服务 → Agent 测评」用一套可维护的题库让多个模型各自走真实的 Agent 运行，再自动评分并排行。它复用 CLI 的离线评测和运行器：`scripts/evals/agent-cases.json` 是内置题库，`src/lib/agent/eval/runner.server.ts` 同时供 CLI（`pnpm eval:agent`，保留离线模式与 `--live --config`）和后台使用。

- 题库：内置题在第一次读取时导入 `agent_eval_cases`，之后可在后台修改、停用；自定义题可增删。题目含工具、体系、题面、断言、工具参数与可选的「先排盘」配置，视觉题另有标记。
- 发起：选择参赛模型、评审模型、题目与重复次数；题目 × 模型 × 重复次数最多 200 次，发起前显示预计调用数（另加最多同数量的质量评审调用）。运行进入独立的 BullMQ `agent-eval` 队列，并发为 1，不参与用户任务的领取，也不占用用户的并发槽。
- 评分：硬检查调用 `assertAgentEvaluation`，核对是否调对工具，并用 Core 按同一份参数与稳定随机种子逐字段复算计算结果与详查缓存；质量检查把题面、断言、答案和 Core 规范文本交给评审模型，只判断列出的断言与答案实际引用的盘面依据。硬检查未通过或评审不可用的结果不参与质量通过率。
- 结果：`agent_eval_runs` 记录发起人、模型、评审模型、题目范围、重复次数、进度与状态；`agent_eval_results` 逐题记录硬检查与质量结果、未通过的断言、答案、评审原文、耗时、首字延迟、token、工具调用数与工具轨迹。三张表都只允许管理员读写。
- 后台页显示进度并可取消（排队中的立即结束，运行中的在下一题前停止）；排行榜按模型给出硬检查通过率、质量通过率、平均与 P95 耗时、首字延迟与平均 token；逐题对比把两个模型的答案并排显示，附未通过的断言和工具轨迹。
- 命令行：`pnpm eval:agent` 跑离线层，不调用模型，只核对工具装配与 Core 复算；`node scripts/eval-agent.mjs --live --config <private.json> --output <report.json>` 叠加真实模型作答与评审打分，私人配置含 `apiKey`、`modelId`、`apiUrl`，用完即删。只跑一题加 `--case <id>`，中断后用 `--resume` 续跑（已完成执行的题只重打分），`--timeout` 调单题执行上限、`--judge-timeout` 调评审上限。用例在 `scripts/evals/agent-cases.json`，新增体系或方法时一并补。
- 隔离：测评使用内存中的 `EvalAgentStore`，不创建 `agent_runs`、不计费、不读写用户资料；功能开关由运行器注入（固定为全部开启），跑评测不会被平台的功能开关或余额挡住。模型调用仍消耗所选模型来源的额度，请按需控制题量与重复次数。

## 命盘与保存

工具卡片使用实际返回的结构化产物，复用各占术已有视图。展开、固定或恢复命盘只展示已有结果，不重新排盘或调用模型。数据不完整时降级为规范文本。

桌面可固定到工作区，移动端使用全屏视图。工作区按账号与会话隔离；工具卡片和最终回复中的同一产物按 `artifactId` 去重。

工作区「概览」只列本对话的成果：命盘与推演结果、对话资料，以及计划模式提交的「分析计划」（最新版在最前，修订与批准按时间排开）。读过的资料、提过的问题、写入的记忆与档案不在这里另列一遍——它们的每一步都在聊天里的任务过程中，点开即到对应页面；工具搜索也能按标题找到没打开的页面。聊天框下方的上下文环按消息、工具、系统提示与压缩缓冲分解用量，「技能」一行列出本任务用过的方法与技能（方法与技能共用一段目录随任务注入系统提示，正文由 `load_skill` 读入上下文），点开方法即到该卡的方法页。

聊天里的任务过程按连续的工具调用、思考与提问分组：每个搜索步骤在行内列出命中的来源与编号，资料、笔记与会话检索列出读到的条目，工具搜索点名加载了哪些工具，子代理调用可展开它当时的参数与返回。思考行默认只显示标题，展开后才显示内容。回答末尾的来源链接只在任务没有搜索步骤时出现，避免与步骤内的来源重复。

任务完成不会自动把命盘或分析保存到用户档案。用户主动保存时，服务端验证任务与产物归属，保存已有计算结果，并保持幂等。长期记忆需要用户开启；归档事件绑定用户提供的事实、所属命盘与来源，编辑或删除时遵循现有来源边界。

## 设置与展示

`/settings` 进入 `/settings/general`。设置导航覆盖常规、账户、钱包、用量日志、个性化、自定义模型（BYOK）、命盘、知识库、技能、连接器、MCP 和帮助；管理员配置入口继续执行服务端管理员检查。

分类切换保留当前工作区的草稿，离开时使用统一草稿保护。切换账号重新挂载面板，隔离上个账号的状态。旧 `#settings/...` 地址通过兼容桥转到页面路由。

浅深主题、字号和减少动画统一使用应用设置与 `src/app/globals.css`。命盘语义配色和普通回复的 Markdown、图表渲染沿用共享组件。

空对话页会打开 Beta 功能弹窗：左侧列出 Agent、多模型协作、长期记忆、技能、连接器、定时任务、钱包与用量日志，右侧给出说明、能力点和入口。列表跟随模块开关，被关闭的功能不出现；只有 Agent 本身不可用时，Agent 相关条目才整组隐藏，单独关闭某项 Agent 工具范围不影响展示。每个用户一份「不再显示」；Esc、遮罩、关闭按钮与点入口只收起本次，本次页面内不再弹出，刷新后重新出现。
