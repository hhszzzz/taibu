# 设计系统与 UI 组件规范

本文定义太卜的视觉语言、组件边界和交互验收标准。目标是让不同页面像同一个产品，而不是让每个页面各自实现一套按钮、菜单和弹窗。

基础组件的逐件规格、ASCII 线框和迁移映射见 [基础组件设计](components.md)。

## 1. 设计原则

1. **内容先于装饰**：命盘、文字解读、会话和表单是主角。卡片、阴影、图标只用于建立层级，不为“组件化”增加无意义容器。
2. **语义先于字面值**：颜色、尺寸、动效先表达页面、表面、文字、危险、选中、五行等语义，再映射到具体数值。
3. **交互一致先于局部巧思**：相同动作使用相同控件和键盘行为；特殊交互必须证明公共组件无法表达。
4. **可访问性属于完成定义**：鼠标可用不等于完成，键盘、焦点、缩放、读屏语义和减少动画同属验收范围。
5. **保留产品识别度**：shadcn 是源码与组合工具，不是太卜的新视觉主题。现有 claude.ai 对齐规格、五行配色和盘面布局不因组件替换而漂移。

## 2. 技术决策：shadcn + Base UI + 太卜令牌

### 2.1 目标架构

UI 基础层采用：

- **shadcn registry**：分发可审查、可修改的组件源码和组合模式；组件进入仓库后由项目维护。
- **Base UI**：承担 Select、Menu、Popover、Tooltip、Dialog 等复杂组件的无样式行为与可访问性基础。
- **Tailwind v4 + 太卜 CSS 变量**：负责全部视觉，不引入第二套主题。
- **Lucide**：继续作为通用界面图标来源；品牌和专业盘面的定制图形按各自规范维护。

Base UI 的当前包名与 API 以实施时官方文档为准。React Aria Components 可作为复杂日期、国际化日历等场景的备选，但同一类基础组件不得同时引入 Radix、Base UI、React Aria 三套实现。

### 2.2 明确禁止的接入方式

- 禁止导入 shadcn 默认全局主题、`shadcn/tailwind.css` 或整套预设覆盖 `globals.css`。
- 禁止把 shadcn 的 `--primary`、`--accent` 含义直接套到项目。太卜当前 `primary` 用于主文字、`accent` 用于品牌强调，语义不同。
- 禁止 CLI 未审查就覆盖已有组件、样式或配置。生成文件必须逐个检查并改为太卜令牌。
- 禁止业务页面直接依赖 Base UI/shadcn 内部结构；业务代码只依赖项目共享组件的稳定接口。
- 禁止为了“使用组件库”把领域命盘、星曜宫格、塔罗牌阵拆成无意义的通用零件。

### 2.3 当前实现与目标状态

`Button`、`IconButton`、`Field`、`Input`、`Textarea`、`Select`、`Switch`、`Checkbox`、`RadioGroup`、`SegmentedControl`、`Tabs`、`Dialog`、`Menu`、`Popover`、`Tooltip` 等共享基础组件已在 `src/components/ui` 落地；`SettingsControls`、`SettingsSwitch` 是设置页的薄封装。业务代码只通过 `Dialog` 打开对话框：结构化模式使用共享标题/说明/页脚，`bare` 模式保留实测外壳；`Modal` 仅作为 `Dialog` 内部的 top-layer 表面。新代码不直接导入 Base UI，也不新写按钮/输入/浮层交互。

目标迁移完成的标准不是“目录里出现 shadcn 文件”，而是：公共交互契约一致、业务调用完成迁移、旧实现和死样式删除、回归验证通过。

## 3. 设计令牌

### 3.1 事实来源

- `src/app/globals.css`：应用语义令牌、Tailwind 映射、明暗主题、基础焦点与全局行为。
- `src/app/cds-tokens.css`：与现有设计规格对应的底层令牌。
- `src/components/ui/overlays.css` 及组件局部 CSS：只表达对应组件的结构和状态，不另建全局色板。

新增视觉值前先判断能否复用令牌。若确需新令牌，必须同时定义明暗主题、说明语义并找到至少一个真实使用场景；不为一次性字面值创建抽象。

### 3.2 颜色使用

| 语义 | 当前代表令牌 | 使用规则 |
| --- | --- | --- |
| 页面/次级背景 | `--background`、`--background-secondary` | 页面层级，不用于任意文字 |
| 卡片/浮层表面 | `--surface`、`--panel` | 有边界或浮起的内容表面 |
| 主/次/弱文字 | `--foreground`、`--foreground-secondary`、`--foreground-tertiary` | 弱文字不能承担唯一关键信息 |
| 品牌强调 | `--accent`、`--accent-hover`、`--accent-soft` | 主操作、选中、焦点；不大面积滥用 |
| 分隔与描边 | `--border`、`--border-hover`、`--hairline-color` | 统一发丝线，不新增近似灰色 |
| 交互填色 | `--fill-ghost-hover`、`--fill-field`、`--fill-control` | ghost、字段与控件状态 |
| 状态 | `--success`、`--warning`、`--danger` | 必须同时有文字/图标，不只靠颜色 |
| 五行/四化 | `--wx-*`、`--element-*`、`--hua-*` | 仅使用既定语义，不在领域组件另配色 |

通用 TSX/CSS 不写新的十六进制、RGB/HSL 字面色。图表渐变、SVG 和品牌资源确有特殊颜色时，使用明确的领域令牌或资源规范，并在评审中说明；不能用“图表例外”绕过普通界面按钮、文字的语义色要求。

### 3.3 排印

- 正文与控件使用 `--font-sans`；代码使用 `--font-mono`。
- `--font-display` 只用于 h1、品牌/问候和既定状态标题，不给所有标题或按钮套衬线。
- 字号使用 rem，保证 `ThemeProvider` 的 root font-size 档位有效；不为局部视觉微调改用 px。
- 中文正文优先可读行高和合理行宽，不用过密文字填满容器。辅助文字与正文至少建立一级明确层级。
- 数字表格、时间和参数需要对齐时使用等宽数字或 mono，不改变整页字体。

### 3.4 尺寸、圆角、线条与阴影

- 常规控件高度沿用 `--control-h`（当前 32px）；紧凑菜单行沿用 `--row-h`，抽屉行沿用 `--row-h-drawer`。
- 圆角使用 Tailwind 映射的 `--radius-*`，区分 chip、控件、行、卡片和 composer；不随机增加相邻近似值。
- 描边使用 `--hairline` / `--hairline-color`。当前 0.5px 发丝线是产品设计的一部分，不应被 shadcn 默认 1px border 全面替换。
- 阴影使用 `--shadow-panel-*`、`--shadow-raised` 等语义。普通内容区不随意浮起，浮层阴影不能与页面卡片混用。
- 浮层层级使用 `--z-toast`、`--z-tooltip`、`--z-popup`、`--z-dialog`；不同时靠更大的任意 z-index 解决嵌套。
- 间距优先使用既有 Tailwind 刻度，形成 4/8px 等稳定节奏；避免连续出现 13、17、19px 等无体系偏移。

### 3.5 动效

- 时长和曲线使用 `--duration-*`、`--ease-*`，组件不另写任意动画参数。
- 动效表达出现、消失、状态变化和空间关系，不阻塞读取、输入或连续操作。
- 退场完成前保留必要语义与焦点管理；后台标签页或动画事件不触发时必须有确定收尾。
- `prefers-reduced-motion: reduce` 下取消非必要位移、缩放和平滑滚动，不能只把动画略微加快。
- 不为所有悬停添加颜色、位移、缩放三重效果；一个状态通常一个主要反馈足够。

## 4. 组件分层与 API 规范

### 4.1 三层边界

| 层级 | 例子 | 职责 |
| --- | --- | --- |
| 基础原语 | Button、Input、Select、Dialog、Tooltip | 视觉变体、原生属性、键盘/焦点、基础状态 |
| 通用模式 | ConfirmDialog、StatePanel、Field、Toast | 跨领域重复的产品行为与内容结构 |
| 领域组合 | ModelSelector、ChartPickerModal、盘面与 composer | 业务数据、领域交互和页面组合，不进入基础原语 |

一个组件只有被两个以上真实场景需要、接口稳定且不携带单一业务假设时，才上升为共享组件。不要根据“以后可能复用”提前抽象。

### 4.2 公共组件接口

- 尽量透传对应原生元素的属性、事件和 ref；禁止用一套简化 props 丢掉 `name`、`required`、`aria-*`、`data-*` 等能力。
- 视觉差异使用有限的 `variant`、`size`、`tone`，行为差异使用语义 props；不堆叠含义重叠的布尔值。
- `className` 只用于布局或明确扩展，不允许调用方通过覆盖内部类名制造第三种变体。
- 受控/非受控模式只有在确有需求时提供；受控值、空值和禁用项语义必须明确。
- 异步 loading 与 disabled 分开：loading 通常阻止重复提交并给出状态，disabled 说明当前为何不可用。
- children 用于内容组合；标题、说明和可访问名称的关联由组件保证唯一 id，不让调用方重复手写易错样板。
- 公共组件不能偷偷读取路由、Session、QueryClient 或领域 API；需要这些数据时由组合层注入。

### 4.3 必备状态

每个交互组件至少审查：default、hover、focus-visible、active/pressed、selected/checked（适用时）、disabled、loading（适用时）、error/invalid（适用时）、dark、reduced motion。缺少状态设计时不能只做“正常样子”。

## 5. 核心组件交互契约

以下为目标公共契约。具体实现可以重写，行为验收不能省略。

### 5.1 Button 与 IconButton

- 普通动作用 `<button type="button">` 语义；表单提交显式 `type="submit"`，不依赖浏览器默认推断。
- 主按钮每个操作区原则上最多一个；危险按钮只用于真正破坏性或高成本动作。
- 图标按钮必须有可访问名称；Tooltip 不能代替 `aria-label`。
- loading 时保留原宽度，避免布局跳动；不得只显示无名称 spinner。
- Enter/Space 激活，禁用态不进入 Tab 顺序；链接导航使用 Link/`a`，不要伪装成按钮。

### 5.2 Input、Textarea 与 Field

- 可点击 label 与控件正确关联；描述、错误通过 `aria-describedby` 关联，错误状态用 `aria-invalid`。
- placeholder 只提供示例或提示，不能代替持久 label。
- 错误文案说明如何修正，不只写“参数错误”；校验失败不应清空用户已输入内容。
- 提交中保留必要上下文；若允许继续编辑，必须处理旧响应覆盖新输入的问题。
- 移动键盘、自动填充、拼写检查和输入模式按字段语义设置，不全局关闭。

### 5.3 Select / Combobox

- 单选 Select 与可输入过滤的 Combobox 是不同模式，不用一个布尔值勉强混合。
- 支持鼠标/触屏、ArrowUp/ArrowDown、Home/End、Enter/Space、Escape、typeahead 和禁用项跳过。
- 打开后选中项或可选项可见；关闭后焦点返回触发器，Tab 按约定离开而不是困住用户。
- 值变化由明确用户动作触发；hover/active descendant 不等于已提交选择。
- 弹层需处理视口边界、滚动、缩放、长选项和移动宽度；不能使用简单 `position: absolute` 假设所有容器都合适。

### 5.4 Switch、Radio 与 Tabs

- Switch 用于立即生效的二元设置，使用 `role="switch"` 与 `aria-checked`；需要“保存后生效”的选项优先 checkbox/按钮加保存动作。
- Radio group 使用 roving tabindex，方向键移动并选择；卡片外观不改变 radio 语义。
- Tabs 的方向键、Home/End、tab/panel 关联符合 APG。面板切换廉价且立即可见时可自动激活；会发起昂贵请求时采用手动激活。
- 不能只靠滑块位置、背景色或图标表达选中，必须暴露真实状态。

### 5.5 Menu 与 Popover

- Menu 只承载一组命令/选项；含输入、任意说明或复杂表单时使用 Popover/Dialog，不硬塞 `role="menu"`。
- Menu 支持方向键、Home/End、typeahead、Escape；子菜单处理进入/离开、边界翻转与焦点返回。
- 多个浮层叠加时只有最上层响应 Escape 和外部点击；关闭子层不能连带关闭父 Dialog。
- 打开后焦点位置有明确策略；动作完成后的焦点返回不依赖偶发点击目标。
- 模型、方法等长列表需要搜索或虚拟化时，保持键盘 active 项与可视滚动同步。

### 5.6 Dialog 与 ConfirmDialog

- 有明确标题，必要时有关联描述；打开后焦点进入合理位置，Tab 不逃出模态区域，关闭后返回触发元素或合理后继元素。
- Escape、遮罩点击和关闭按钮行为一致；busy/危险提交中是否禁止关闭必须明确，不能误关后仍产生不可见写入。
- 内容可滚动，标题/操作区在窄屏可达；软键盘和安全区域不能遮挡主操作。
- ConfirmDialog 只用于不可逆、破坏性、高成本或用户可能误解后果的动作。说明具体对象与后果，主按钮写“删除记录”等动作，不写笼统“确定”。
- 不用 Dialog 展示普通页面导航或可内联完成的简单说明。

### 5.7 Tooltip 与 Toast

- Tooltip 只放简短补充说明，不放交互控件或完成任务所必需的信息；hover 与 focus 都可触发，Escape 可关闭，触屏不能依赖 hover。
- Toast 用于低风险、短反馈，不承载必须阅读的长错误、表单校验或需要用户决定的关键流程。
- 成功、失败、警告样式与可访问通知语义一致；连续事件不无限堆叠或遮挡主操作。
- 关键错误必须同时留在对应页面/字段附近，不能几秒后完全消失。

### 5.8 StatePanel 与 Loading

- 空状态说明“没有什么”以及下一步能做什么；错误状态说明失败与可重试动作，二者不混用。
- 全页、列表内、局部面板使用不同密度，但复用同一 `StatePanel` 语义。
- 加载优先保留已有内容，避免整页闪烁；骨架/loader 不应造成明显布局跳动。
- 无数据、无搜索结果、无权限、功能关闭、加载失败是不同状态，文案与图标不得混用。

## 6. 响应式、触屏与缩放

- 采用内容驱动布局，不以设备型号堆叠断点。至少走查 320、390、768、1024、1440 CSS px 和中间临界宽度。
- 320px 下不得出现页面级横向滚动；数据表/代码等确需局部滚动时限定在内容容器并可见可操作。
- 弹层同时考虑 `visualViewport`、安全区域和软键盘；不能只在桌面 100vh 下验证。
- WCAG 2.2 AA 的目标尺寸基线为 24×24 CSS px（标准允许的例外除外）；高频触屏操作应提供更大有效区域。视觉图标可小于点击区域。
- 200% 文本/页面缩放后，内容不丢失、控件不重叠、功能不消失。现有用户字号档位也必须验证。
- hover 才出现的操作必须能通过 focus 和触屏发现；关键操作不能完全依赖 hover。

## 7. 可访问性验收

目标为 WCAG 2.2 AA 的相关适用条目，但“用了 Base UI”不等于自动合规。每个共享组件和代表页面至少验证：

1. 仅键盘能完成主要流程，Tab 顺序符合视觉与任务顺序。
2. focus-visible 清晰，不被 sticky/overflow 遮挡；打开/关闭浮层后焦点位置合理。
3. 名称、角色、值、选中/展开/禁用/错误状态正确；没有重复 id 和悬空 aria 引用。
4. 普通文字对比度至少 4.5:1，大号文字至少 3:1；必要非文字控件与状态至少 3:1。
5. 状态变化通过适当 live region 通知，但不过度播报流式 token 或连续进度。
6. 减少动画、明暗主题、字体放大和 200% 缩放不破坏任务。
7. 自动工具只用于发现部分问题；键盘、焦点、读屏和实际任务仍需人工验证。

## 8. 领域 UI 的特别约束

- 盘面、图表和塔罗等领域组件保留自己的结构与视觉密度，但普通按钮、输入、菜单、对话框仍使用共享体系。
- 五行、四化、吉凶等语义不能只靠红绿区分；文字、符号或图形必须能独立表达。
- Agent 详查、定位、展开和保存依赖的目标 `data-*`/结构契约不能因换组件而丢失。
- 新增盘面 UI 必须遵守“模型当前查看的内容可见”：详查、定位、读取整盘均属于正在查看，不因面板切换而隐藏。
- 图表导出、分享、暗色主题和静态快照需要分别验收，不能只检查浏览器内交互态。

## 9. 文案与反馈

- 使用简短、具体、可行动的中文。按钮优先动词：“保存更改”“删除记录”“停止生成”。
- 错误先说结果，再给可执行下一步；不向用户暴露 SQL、堆栈、内部主体或未处理英文异常。
- 不用夸张、拟人或营销形容词填充设置与错误状态。
- 不用浏览器 `alert`；统一使用页面内错误或 Toast，关键流程使用 Dialog/Field。
- 删除、取消、停止、关闭的含义保持全站一致，不能同一词语在不同页面产生相反后果。

## 10. 迁移与完成清单

推荐顺序：共享令牌/基础组件 → Select 与浮层行为回归 → 设置与后台 → 认证/占测/业务页面 → 聊天与 Agent 工作区 → 删除旧实现。每阶段只迁移一种或一类边界，避免同时改业务逻辑。

### 组件完成定义

- [ ] 使用语义令牌，明暗主题和字体档位正确。
- [ ] 公共 API 透传必要原生属性，未泄露领域依赖。
- [ ] 键盘、焦点、禁用、loading、错误和 reduced motion 已验证。
- [ ] 窄屏、触屏、视口边界和缩放已验证。
- [ ] 行为测试覆盖公开契约，真实页面完成视觉走查。
- [ ] 调用方、测试和文档同步，旧实现与死样式已删除。
