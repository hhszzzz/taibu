# 前端工程规范

本文约束 `src/app`、`src/components` 与浏览器侧 `src/lib`。视觉和组件交互细则见 [设计系统](design-system.md)。

## 1. 模块边界

| 位置 | 应放内容 | 不应放内容 |
| --- | --- | --- |
| `src/app/**/page.tsx` | 路由组合、元数据、服务端数据入口、轻量页面编排 | 大段可复用业务逻辑、数据库连接、复杂交互状态机 |
| `src/app/api/**/route.ts` | HTTP 参数、鉴权、响应与用例编排 | React 状态、浏览器依赖、算法实现 |
| `src/components/ui/` | 无领域依赖的基础组件与通用反馈模式 | Session/路由/具体占术 API、某个页面的专有布局 |
| `src/components/<domain>/` | 领域组件、组合、展示与局部交互 | 另一领域的算法、重复基础设施 |
| `src/lib/` | 可复用业务、数据契约、hooks、浏览器/服务端适配 | 仅服务一个 JSX 片段的样式细节 |
| `src/lib/**/*.server.ts` | 只能服务端使用的配置、DB、密钥与运行时 | 客户端 import、浏览器全局对象 |
| `packages/core/` | 占术算法、规范文本/JSON 与公共领域契约 | Web、数据库、认证、React 依赖 |

先检索后实现。已有组件能满足需求时，通过组合或小幅扩展复用；不得复制后改名形成第二套公共能力。

## 2. Server 与 Client Component

### 2.1 默认选择

默认使用 Server Component。只有需要浏览器事件、本地状态、effects、浏览器 API 或客户端 hooks 时，才把对应节点标记为 `'use client'`。

- 客户端边界尽量下沉到交互叶子，不给整页或根布局无必要地加 `'use client'`。
- Server Component 负责可服务端完成的数据读取与静态组合；Client Component 通过可序列化 props 接收数据。
- 不要把函数、数据库事务、服务端实例或不可序列化对象从 Server 传入 Client。
- 服务端模块显式使用 `server-only` 和 `.server.ts` 约定；客户端文件不得导入 DB、identity、私有 AI 配置或其他服务端模块。

### 2.2 密钥与数据边界

客户端只能读取构建时允许公开的 `NEXT_PUBLIC_*` 和 `NODE_ENV`。任何“浏览器拿不到就安全”的假设都不成立：客户端源码、source map、props 和网络响应都应视为用户可检查。

只把页面需要的数据传给客户端。不要因为类型方便把完整数据库行、密钥配置、其他用户资料或内部权限字段塞进 props。

## 3. 组件设计

### 3.1 文件与导出

- React 组件文件使用 PascalCase，组件名与文件主要导出一致；hooks 使用 `useXxx`。
- 优先命名导出；Next.js 页面、布局和框架要求的文件使用其规定的默认导出。
- 一个文件围绕一个主要组件及其私有小组件，不把多个不相关公共组件塞入“utils.tsx”。
- 页面专有组件靠近页面或领域；只有出现真实跨域复用后才移入共享目录。

### 3.2 Props 与组合

- Props 类型表达真实约束，优先判别联合而不是一堆互相冲突的可选布尔值。
- 使用 `children`、具名 slot 或 render 数据组合内容；公共基础组件不感知领域数据结构。
- 透传合理原生属性和 ref，避免包装后失去键盘、表单或测试能力。
- 不通过大对象 prop 隐式传递整页状态；只传组件实际需要的数据和稳定回调。
- 公共 API 的空值、数组顺序、受控行为和错误行为必须明确，不能依赖调用方碰巧传入某种形状。

### 3.3 语义与可访问性

优先原生 HTML，再补 ARIA。`div onClick` 不是按钮；只有真正实现完整键盘、焦点和角色契约时才能使用自定义交互元素。

图标默认装饰性并设置 `aria-hidden`，独立图标按钮必须有名称。标题层级表达页面结构，不为字号选择 `h1`–`h6`。所有浮层、表单、标签和状态通知按 [设计系统](design-system.md) 验收。

模态内容统一由 `Dialog` 提供 top-layer、焦点圈定与关闭语义，业务代码不手写 `role="dialog"`、`role="alertdialog"`、`role="listbox"` 或 `role="option"`。底部导航抽屉是唯一保留的导航外壳例外，由架构守卫按文件放行。

### 3.4 共享控件

普通按钮、图标按钮、输入框、Select、开关、标签页与对话框使用 `src/components/ui` 的共享组件，不新写按钮 class 常量或第二套交互。业务层不直接导入 `@base-ui/react`，需要新行为时先扩展共享组件。

表单字段放进 `Field`，由它注入 `id`、`aria-describedby`、`aria-invalid` 和 `required`，不手写这组关联。给共享组件传 `className` 只做布局或明确扩展；共享组件内部用 `cn()`（clsx + tailwind-merge）合并类名，调用方的冲突类才能可靠覆盖默认值，新写的组件也照此合并，不用模板字符串拼接。

盘面、聊天 composer、Agent 工作区等按实测规格维护的专用控件可以保留既有实现，但应在 `docs/engineering/components.md` 的例外清单中说明原因；新增同类控件不得复制旧写法。

## 4. 状态管理

### 4.1 按事实来源选择位置

| 状态 | 默认位置 | 规则 |
| --- | --- | --- |
| 服务端实体、缓存、失效与请求状态 | TanStack Query | 使用统一 query keys/client，不复制到第二份 Context |
| 可分享/可恢复的页面状态 | URL/search params 或服务端草稿 | 刷新与分享语义明确，避免 URL 与本地状态互相覆盖 |
| 输入、展开、局部选择 | 组件 state | 尽量靠近使用处，不上提给整页 |
| 跨组件瞬时 UI 状态 | 最小 Context 或明确状态模块 | 只放真正共享部分，避免整树因一个字段重渲染 |
| 可由 props/state 推导的数据 | 渲染期计算 | 不用 effect + state 再保存一份 |
| 用户持久偏好 | 现有设置/本地持久化流程 | 服务端与本地事实来源及同步时机明确 |

### 4.2 状态不变量

- 同一数据只能有一个权威写入口。缓存、Context、组件 state 不应各自修改同一列表。
- 初始化默认值与外部值同步要区分；外部值变化不应无意覆盖用户正在编辑的内容。
- 对象/数组更新保持不可变，不直接修改 Query 缓存、props 或共享引用。
- 清理组件卸载、账号切换、路由切换和会话切换后的私有状态，防止数据串户。

## 5. Effects 与渲染

Effect 只用于与外部系统同步，不用于普通派生计算或“props 变了就 setState”的惯性别名。

- 依赖数组完整且真实，不为压过 lint 随意省略；需要稳定引用时先修正数据流。
- 订阅、计时器、observer、事件监听和请求都必须清理。
- effect 中发请求要处理竞态、取消和过期响应；旧请求不能覆盖新参数结果。
- 不在渲染期间写 DOM、localStorage、网络或修改其他组件状态。
- `useMemo`/`useCallback` 用于有证据的昂贵计算或引用契约，不默认包裹每个值。
- 列表 key 使用稳定身份，不使用会随排序/插入变化的数组下标。

现有 React Compiler lint 警告不应被当成永久豁免。触碰相关文件时应修正真实依赖/渲染问题，而不是新增 eslint-disable。

## 6. 数据请求与异步交互

### 6.1 Query 使用

- 复用 `src/lib/query/keys.ts`、统一 QueryClient 和失效映射，不在组件里另写近似 key。
- query key 包含所有影响结果的参数与身份；账号变化必须隔离私有缓存。
- mutation 成功后按依赖精确失效，不无差别清空整库；乐观更新必须可回滚。
- 请求失败保留可恢复状态，不把错误转成看似成功的空数组。

### 6.2 表单与提交

- 原生表单语义优先，提交按钮、Enter 行为和 pending 状态一致。
- 防止重复提交，但不要在请求尚未确定前清空输入。
- 客户端校验用于即时体验，服务端校验仍是安全边界。
- 错误靠近字段或操作区，成功反馈与页面状态一致；不能 Toast 显示成功但 UI 仍展示旧数据。
- 多步表单明确每步事实来源、返回修改、刷新恢复和最终提交幂等性。

### 6.3 流式、长任务与取消

- 流式内容使用明确生命周期，处理开始、增量、完成、失败、取消和重连，不通过字符串拼接猜测最终状态。
- 用户取消后停止相关网络/后续状态更新；网络取消不等于服务端任务已取消，二者需分别确认。
- 长任务离开页面后通过现有任务体系恢复和通知，不依赖页面组件永远存活。
- 旧流、旧任务或旧账号的回调不得写入当前视图。

## 7. 样式与资源

- 使用 Tailwind 与语义令牌；复杂结构、伪元素或状态选择器可放组件邻近 CSS。
- 不用内联 `style` 重写设计变体；动态位置、尺寸和确需运行时计算的值可以使用内联样式。
- 不用 `!important` 解决层叠顺序，先修正选择器、层级或组件边界。
- z-index 按页面/浮层体系集中管理，不能通过不断增加数值解决遮挡。原生模态框（`showModal`）位于 top layer，z-index 对它无效；对话框内的浮层与全局提示要挂进对话框，见 [设计系统 §3.4](design-system.md#34-尺寸圆角线条与阴影)。
- 组件邻近 CSS 是未分层样式，会压过 Tailwind 工具类；不要在共享 CSS 里用宽泛选择器改写共享组件的 outline、背景等状态（原对话框焦点规则就因此盖掉了所有组件的焦点样式）。
- 图标复用 Lucide、品牌和领域图标入口；同一功能不在不同页面换用风格冲突的图标。
- 图片提供合理尺寸、替代文本和加载策略；纯装饰图片使用空 alt。
- 不为局部功能引入新的全局字体、CSS reset 或主题 Provider。

## 8. 渲染安全

- 用户文本、模型输出、知识库内容和外部网页都视为不可信输入。
- Markdown 使用现有 `MarkdownContent` 及其链接/代码/来源策略，不在业务页面另写 HTML 注入。
- `dangerouslySetInnerHTML` 只允许有明确可信来源和安全约束的基础场景；不能把模型或用户 HTML 直接注入。
- URL 不仅检查字符串非空，还要限制允许协议；拒绝 `javascript:` 等危险链接。
- `visual`/iframe、导出 HTML 等沙箱能力保持 CSP、脚本禁用和主题消息边界，不为展示效果放宽。
- 不把访问令牌、私有附件签名或用户敏感内容写入日志、公开分享页和截图。

## 9. 性能与包体

先测量再优化。优化不能牺牲状态正确性和可访问性。

- 保持客户端边界小，避免把大型 Markdown、图表、PDF、编辑器依赖带入首屏公共 chunk。
- 大型非首屏模块使用合适的动态加载，但关键交互要有稳定加载态，避免布局跳动。
- 长会话、模型列表和大型结果沿用现有虚拟化方案；虚拟化必须保留键盘焦点、滚动定位和可访问语义。
- 图片、文件和图表按视口与任务需要加载，不预取用户不会访问的大资源。
- 避免无界缓存、事件监听和对象 URL；释放 URL、worker、observer 和定时器。
- 新依赖先评估是否已有浏览器/Web 标准或仓库能力可实现，并检查包体、维护与许可。

## 10. 错误、空态与降级

- 页面区分加载、空数据、无权限、离线/请求失败、功能关闭和部分失败。
- 局部增强失败时保留核心内容。例如分享卡片导出失败不应丢掉原始结果，图表失败应能展示已有规范文本。
- 重试必须有界且由明确策略控制；用户主动重试与自动重试不能叠加成请求风暴。
- Error Boundary/路由 error 页面提供可恢复动作，不展示内部堆栈。
- 功能不支持时诚实说明，不伪造空结果、进度或成功状态。

## 11. 前端完成清单

### 结构

- [ ] Server/Client 边界合理，无服务端密钥和私有数据泄漏。
- [ ] 复用现有组件、Query keys、hooks 和业务模块，无平行实现。
- [ ] 状态只有一个事实来源，effect、订阅和异步均有清理。

### 交互与视觉

- [ ] 使用设计令牌和共享控件，未引入默认第三方皮肤。
- [ ] 键盘、焦点、表单错误、loading、disabled 和取消行为已验证。
- [ ] 明暗主题、字号档位、320/390/768/1440、200% 缩放和 reduced motion 已检查相关页面。

### 数据与安全

- [ ] 请求处理竞态、重复提交、失败和账号/路由切换。
- [ ] 用户/模型/外部内容按不可信输入处理，链接和 HTML 策略未放宽。
- [ ] 测试与文档同步，旧实现和无用资源已删除。
