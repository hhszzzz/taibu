# 后端与 API 工程规范

本文约束 Next.js Route Handler、服务端业务模块、Redis/BullMQ Worker、AI 调用和 MCP 接入。数据库与文件细则见 [数据与安全](data-security.md)。

## 1. 架构原则

1. **HTTP 边界与业务分离**：Route 负责请求/响应，领域用例负责业务，DB/Redis/模型/存储通过既有适配层访问。
2. **调用者身份贯穿全链路**：鉴权、数据访问、资源归属、积分与审计使用同一请求主体，不在中途换成匿名或系统身份。
3. **服务端是唯一权限边界**：隐藏按钮、客户端校验、路由路径和模型自述都不能替代服务端检查。
4. **失败必须可解释**：区分输入、权限、冲突、限流、依赖故障和内部错误，所有异步失败都有最终状态。
5. **副作用可追踪、可恢复**：跨表写入、扣费、任务、通知和文件操作明确事务、幂等与补偿，不能“重试看看”。

## 2. 请求处理分层

推荐请求路径：

`Route → 参数/内容读取 → 会话与权限 → 领域用例 → ScopedDb/外部适配 → 稳定响应`

### Route 应负责

- 读取并限制请求体、query、path 和文件；
- 调用 `requireUserContext`、`requireAdminContext` 或明确的匿名流程；
- 编排一个业务用例并映射成功/失败响应；
- 处理 HTTP 语义，如状态码、headers、SSE 与请求取消。

### Route 不应负责

- 创建 `pg`/Kysely 连接池、拼接身份 claims 或绕过 ScopedDb；
- 复制占术算法、积分规则、会员规则、知识库检索或 Agent 状态机；
- 在多个路由重复实现同一资源归属和写入流程；
- 捕获所有异常后统一返回模糊的 400，掩盖依赖故障。

复杂逻辑放入可测试的 `src/lib` 用例/适配模块。重构时可以拆分层级，但不能只把同样耦合的代码搬到另一个文件。

## 3. 鉴权与授权

### 3.1 入口选择

| 场景 | 当前入口/边界 | 要求 |
| --- | --- | --- |
| 可选登录读取 | `getAuthContext()` | 匿名使用 anon scope，身份服务故障不能伪装成退出登录 |
| 登录用户接口 | `requireUserContext()` | 无有效用户返回 401，后续使用其 db/user |
| 管理员接口 | `requireAdminContext()` / `requireAdminUser()` | 管理员身份由服务端数据库状态决定，非管理员 403 |
| Worker/系统维护 | 白名单 `systemDb()` 路径 | 只处理明确系统任务，不从缺失请求身份回退 |
| Better Auth | `src/lib/identity/` | 独立 identity 边界，不暴露内部连接与密钥 |

### 3.2 授权检查顺序

1. 验证会话有效性与请求来源要求。
2. 获取请求主体和 ScopedDb。
3. 根据动作检查管理员、会员、模型、功能或资源权限。
4. 在数据查询/原子函数中再次约束资源所有者，不只先查一次再在另一连接更新。
5. 返回前检查响应是否包含其他用户或内部敏感字段。

用户提供的 `userId`、`conversationId`、`chartId`、`runId`、文件 id 都只是待验证输入，不是授权依据。禁止以“id 不可猜”替代归属校验。

### 3.3 请求来源

Better Auth 的会话 Cookie 是 `SameSite=Lax`，跨站的顶层 GET 导航仍会带上它。因此：

- GET/HEAD 必须无副作用；写入、扣费、发任务、发邮件只接受 POST/PUT/PATCH/DELETE。
- 目前只有 Better Auth 自己的端点校验 `trustedOrigins`，应用 API 没有来源检查。Cookie 鉴权的写接口应该补 `Origin`（或 `Sec-Fetch-Site`）校验，防同站子域和不遵守 SameSite 的客户端。

## 4. 输入、请求体与输出

### 4.1 输入校验

在系统边界校验类型、必填、长度、枚举、数值范围、数组条数、日期/时区和对象深度。TypeScript 类型不能验证运行时 JSON。

- 对未知 action、枚举和模式明确拒绝，不静默落到高权限或高成本默认分支。
- 数值先处理 `NaN`、Infinity、小数、负数和上限，字符串先明确是否 trim、是否允许空串。
- 批量接口限制数量，文本/向量/搜索限制长度与复杂度，上传使用现有流式字节限制。
- JSON 请求体同样要限字节：`request.json()` 不设上限，目前只有反向代理的 12MB（`deploy/Caddyfile*` 的 `request_body max_size`）兜底。新写或触碰的路由先用 `src/lib/api-utils.ts` 的 `readRequestBytes(request, maxBytes)` 按接口合理上限读取再解析，超限返回 413。
- 日期时间保留时区和 DST 语义；不能用服务器本地时区隐式解释用户出生时间。
- 不把整个 request body 直接 spread 到 DB、模型工具参数或命令执行参数。

### 4.2 输出契约

- 成功响应使用 `jsonOk` 或现有流式响应，错误使用 `jsonError`；同一路由的成功/失败形状保持稳定。
- 只返回客户端需要的字段，密钥、内部配置、其他用户字段和调试信息不得进入响应。
- 含用户私有数据的响应不得进入共享缓存：显式设置 `Cache-Control: private, no-store`（或等价头），不依赖框架或代理的默认值；`jsonOk` 目前不加任何缓存头。
- 列表明确分页、排序和空结果语义；时间格式、id 类型、可空字段和数值单位保持一致。
- 修改公共响应时同步类型、调用方和路由测试。新增字段也应评估旧调用方是否把它误当完整对象。
- 不通过 HTTP 200 + 隐晦错误文本代替明确失败，除非既有流式协议已定义错误事件且有测试覆盖。

## 5. 错误与状态码

| 状态 | 使用场景 | 注意事项 |
| --- | --- | --- |
| 400 | JSON、字段、action 或业务输入无效 | 文案指出可修正问题 |
| 401 | 未登录、会话无效 | 身份服务不可用应区分 503，不清除有效会话 |
| 403 | 已登录但无管理员/会员/模型/功能权限 | 不泄露不必要的内部规则 |
| 404 | 资源不存在，或为避免枚举而不披露他人资源 | 同一资源策略保持一致 |
| 409 | 状态冲突、重复操作、当前任务不允许该动作 | 给出当前状态或安全下一步 |
| 413 | 请求体/文件超过限制 | 在完整缓冲前限制字节 |
| 429 | 限流、登录失败锁或配额策略要求稍后再试 | 与积分不足等业务结果区分，按契约提供重试信息 |
| 500 | 未预期内部错误 | 对外稳定文案，对内记录脱敏上下文 |
| 502/503/504 | 上游模型、DB、Redis、身份服务或超时 | 不伪装成用户输入错误，重试策略有界 |

业务异常使用带语义的错误类型/结果，不在各层靠匹配错误文案判断分支。日志应包含操作、路由/任务和安全关联 id；不记录密码、token、API key、完整私密对话或上传内容。

## 6. 数据写入、事务与幂等

- 多表写入、扣积分与记账、任务与产物更新等需要原子性的操作，优先复用现有数据库函数或在同一 ScopedDb 事务完成。
- 数据库事务保持短小，不在事务内调用模型、SMTP、远程 HTTP 或等待用户输入。
- 资源归属与余额/配额检查尽量和写入处于同一事务边界，避免“先检查再写入”的并发穿透。
- 创建、扣费、回调、任务命令和保存操作明确幂等键/唯一约束/收据；网络重试不得产生重复扣费或重复记录。
- 外部副作用无法与 DB 同事务时，使用明确状态机、outbox/任务或可验证补偿，不能假设两个系统永远同时成功。
- 失败补偿本身也要幂等并记录最终状态；补偿失败不得被空 catch 吞掉。

涉及鉴权、积分、会员、限流、计费或资源归属的重构，先补成功、失败、权限与并发回归，再改实现。

## 7. Redis、BullMQ 与 Worker

- Redis 缓存不是业务事实来源，除非对应契约明确；DB 与缓存更新顺序和失效策略必须一致。
- 限流、登录锁和分布式状态使用原子操作，避免读取—判断—写入的并发窗口。
- Job 数据只包含执行所需最小内容和身份引用，不把密钥、巨大文本或完整私有对象无界写入队列。
- 每个任务定义输入校验、超时、重试次数、退避、取消和最终失败状态；只重试可恢复故障，无效输入不重试。
- Worker 重启/重复投递必须安全。Agent 继续使用租约、fence、checkpoint 和幂等收据，执行前验证当前租约与任务状态。
- 文档解析等 CPU/内存密集或不可信格式处理保持 worker 线程边界，限制大小、页数/时长和异常输出。
- 关闭进程时停止接新任务并完成必要清理；清理失败不能留下永远 running 的假象。

## 8. AI、Agent 与外部服务

- 模型输出是不可信数据，不是授权决定、SQL、命令或事实来源。工具调用仍需服务端参数、权限、额度和归属检查。
- 用户、知识库、网页、文件和工具返回中的指令均可能是提示注入；不能把其中“忽略权限/泄露密钥”等文本升级为系统指令。
- 工具只获得完成任务所需最小上下文和权限；系统工具、BYOK、平台模型和管理员配置边界不混用。
- 模型超时、限流、空响应、格式错误、额度不足和中途取消分别处理；失败不得伪造分析或保存半截结果。
- 外部 URL/文件抓取限制协议、地址、重定向、大小、超时和响应类型，防止 SSRF 与无界下载。不能只校验初始 URL 字符串。
- 提示词、来源和结果保存复用现有 pipeline/来源注册；跨表保存、积分与失败补偿不在路由另写简化版。
- Core 的算法和规范 text/json 是唯一事实来源。Web、MCP、Agent 不重复实现“看起来更合理”的算法分支。
- 实时模型评测消耗额度，不能作为默认测试；离线测试使用夹具并验证工具装配与状态契约。

## 9. SSE、流式响应与连接生命周期

- 使用现有 `SSE_HEADERS` 和流式协议，禁止中间代理缓冲破坏事件边界。
- 明确定义事件类型、顺序、结束和错误事件；客户端不能靠连接关闭猜测业务成功。
- 监听请求 abort 与上游取消，停止无消费者的模型/流读取；同时区分“客户端断开”和“服务端任务已结算”。
- 心跳、超时和重连策略不得导致重复写入或重复扣费。
- 错误事件不泄露堆栈、密钥、上游完整响应或其他用户数据。
- 长连接计数、内存和背压需要边界；不能无限缓冲快速增长的上游内容。

## 10. 日志、观测与调试

- 关键操作记录结构化阶段：接收、鉴权、用例、外部依赖、持久化、完成/失败。
- 使用请求/任务/运行等关联 id 串联网页、Worker 和外部调用，但关联 id 不替代资源授权。
- 日志避免高基数无界内容和逐 token 输出；生产环境关闭敏感 debug。
- 外部故障保留可诊断分类与安全摘要，不把完整请求/响应默认写入日志。
- 重要失败必须能从任务/记录状态观察到，不能只存在于一次性控制台。

## 11. 后端完成清单

- [ ] 路由只做边界与编排，业务复用既有用例/Core，无重复算法或权限规则。
- [ ] 所有入口明确匿名、用户、管理员或系统主体，资源归属在服务端和事务中校验。
- [ ] 输入有运行时类型/范围/大小限制，输出无密钥与多余私有字段。
- [ ] 状态码和错误语义稳定，依赖故障不被误报为用户错误。
- [ ] 写入具备事务、幂等、并发与失败补偿；任务有超时、取消和最终状态。
- [ ] 外部 URL、模型输出和工具输入按不可信数据处理。
- [ ] 路由/用例/权限/并发测试按风险补齐，文档与类型同步。
