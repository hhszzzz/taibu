# 测试与验收规范

测试的目的不是增加数量，而是证明公共行为、权限边界和失败路径在修改后仍成立。视觉、可访问性和真实运行环境需要相应层级的验证，不能由单元测试代替。

## 1. 验证原则

1. **按风险选层级**：改哪一层契约，就至少验证哪一层；跨层修改不能只跑最便宜的测试。
2. **测试公开行为**：优先观察输入、输出、状态、用户操作和可访问语义，不绑定私有变量或任意 DOM 层级。
3. **失败也是契约**：权限拒绝、非法输入、超时、取消、并发、重试和补偿必须有与成功路径相称的覆盖。
4. **隔离且可重复**：测试不依赖真实模型、公网、个人账号、执行顺序或本机遗留数据。
5. **结果如实报告**：通过、失败、跳过和未执行必须区分，不能把构建成功描述成全站验收通过。

## 2. 当前验证入口

| 命令 | 当前覆盖 | 主要限制 |
| --- | --- | --- |
| `pnpm lint` | ESLint 与架构守卫 | 不证明运行时行为或视觉正确 |
| `pnpm typecheck` | 构建所需 packages 后执行应用 strict 类型检查 | 不代替测试 |
| `pnpm test` | 单元、路由、协议与守卫测试，自动构建所需包 | 不包含所有真实基础设施和视觉 |
| `pnpm test:db` | 隔离 PostgreSQL 的 SQL、RLS、并发与原子性 | 需要相应本地隔离环境 |
| `pnpm test:auth` | 本地栈中的 Better Auth 与邮件验收 | 需要本地栈/Mailpit |
| `pnpm test:browser` | 真实 Chromium 中的组件行为，使用合成 API/模型夹具 | 不加载完整应用 CSS，不能证明布局/截图正确 |
| `pnpm build` | Core、Agent worker 与 Next.js 生产构建 | 构建通过不等于业务验收完成 |
| `pnpm verify` | lint、类型、单测、构建、DB、认证、Redis、浏览器等完整序列 | 需要 Docker 与 Playwright 浏览器，耗时更长 |

修改 package 源码后使用上述命令自动构建，不手工复用过期 dist。类型检查和大型测试顺序执行，避免资源竞争导致看似代码故障的假失败。

## 3. 变更—测试矩阵

| 变更 | 必测 | 按需补充 |
| --- | --- | --- |
| 纯函数、Core 算法、数据映射 | 对应单元/快照/边界测试 | 属性/穷举、跨包契约、性能 |
| `src/lib/*` 业务逻辑 | 新增或更新对应单测 | API/DB/Worker 集成 |
| `src/app/api/*` | 路由成功、失败、权限边界至少两类；按实际风险补全 | 并发、限流、积分、流式与取消 |
| 鉴权/会员/积分/限流/计费 | 专项回归，含本人/他人/匿名/并发和失败补偿 | 真实栈认证与任务验收 |
| 数据库/RLS/函数 | `test:db`、当前 SQL/类型一致性、升级验证 | 恢复、迁移重跑、查询计划 |
| 共享 UI 原语 | 浏览器键盘/焦点/状态行为 | 真实页面视觉与读屏 |
| 业务页面交互 | 对应组件行为 + 手动主流程 | 移动、暗色、缩放、异常状态 |
| 纯文案/局部样式 | 相关页面手动验证 | 相关浏览器回归 |
| 跨层/发布前 | `pnpm verify` | 真实栈端到端与部署检查 |

“至少两类”是下限，不是允许遗漏第三种关键权限。一个删除接口即使成功和 400 都通过，若没有他人资源 403/404 测试，仍不算完成。

## 4. 单元与契约测试

### 4.1 应该覆盖

- 正常输入、空值、最小/最大值、非法类型、时区/DST、精度和边界日期；
- 状态机的允许/拒绝转换、重复输入、排序和幂等；
- 数据映射不丢字段、不暴露额外秘密，Core text/json 契约一致；
- 错误分类与重试策略，而不是只断言“抛错”。

### 4.2 测试写法

- 使用 Arrange / Act / Assert 的自然结构，测试名写清条件和预期。
- 一个测试聚焦一个行为，可以有多个相关断言；不为减少文件把无关场景塞成超长流程。
- fixture 使用最小安全数据，工厂函数只在确有复用时提取。
- 快照用于稳定规范输出，不能对大对象无脑快照代替关键断言；更新快照必须审查差异。
- 时间、随机数、id 和排序通过注入/固定策略控制，不依赖真实当前时间造成跨日失败。
- 不通过修改生产代码暴露私有字段只为测试；优先测试公共接口。

## 5. API 与权限测试

每个路由按实际动作建立矩阵：

| 维度 | 典型场景 |
| --- | --- |
| 身份 | 匿名、本人、其他用户、管理员、系统/Worker |
| 输入 | 合法、缺字段、错误类型、超长、未知 action、批量上限 |
| 资源 | 存在、不存在、属于他人、已删除/已归档、分享状态 |
| 状态 | 可执行、冲突、重复提交、处理中、已完成、已取消 |
| 依赖 | DB/Redis/模型/存储失败、超时、部分成功 |
| 副作用 | 只写一次、幂等、账本一致、失败补偿、通知不重复 |

断言不仅包含 HTTP status，还包括响应形状和关键副作用。权限失败必须证明没有写入、扣费、泄露或触发任务。

Route mock 只替换外部边界，保留真实鉴权分支、参数解析与用例逻辑；如果把被测逻辑也 mock 掉，测试就失去意义。

## 6. 数据库契约

- 使用隔离 PostgreSQL，不连接生产或个人业务库。
- 验证当前 SQL 可初始化、差异工具结果符合预期、生成类型与定义同步。
- RLS 分别测试 anon、authenticated、系统主体和不同用户，覆盖 SELECT 与写入 WITH CHECK。
- 原子函数测试余额/配额不足、重复调用、并发、异常回滚、权限和 `search_path`。
- 结构升级在已有数据的隔离库上验证，不只做全新库初始化；检查回填、默认值、约束、索引和重跑行为。
- 备份相关变更执行恢复验证，不只做 dump。

测试结束清理隔离资源，不复用共享栈制造相互污染。

## 7. 浏览器组件测试

现有 `scripts/tests/browser-components.mjs` 使用真实组件和合成 I/O。新增共享组件或迁移高风险区域时，优先在这里覆盖公开行为。

### 7.1 基础组件最低用例

- Button：Enter/Space、submit、disabled、loading 防重复。
- Field：label/描述/错误关联，输入与校验反馈不清空。
- Select/Menu：打开、方向键、Home/End、typeahead、禁用项、选择、Escape、Tab、焦点返回。
- Tabs/Radio：roving tabindex、方向键、选中状态和 panel 关联。
- Dialog：初始焦点、Tab 圈定、Escape/遮罩、busy、退出、嵌套浮层与焦点返回。
- Tooltip：hover/focus/Escape 与触屏策略。
- Toast：通知内容、动作、连续通知、退场与清理。

### 7.2 业务交互重点

- 聊天 composer 的 Enter/Shift+Enter、命令、模型/模式菜单、发送中/取消；
- 侧栏会话菜单、重命名/删除、移动抽屉；
- Agent 工具结果展开、盘面定位、工作区、问题输入和保存；
- 表单校验、长列表、分页、账号切换和缓存隔离；
- 请求 pending、失败、过期响应和重复操作。

不要在离线夹具中断言依赖真实 CSS 的尺寸、颜色或截图。其注释已明确 CSS/layout 不在范围内；这些必须由真实应用走查补足。

## 8. 真实页面视觉与可访问性验收

### 8.1 环境

优先使用连接固定 `taibu-v2` 本地栈的宿主机 `next dev` 查看前端改动，避免纯 UI 变更重建共享镜像。需要使用其他运行方式时，确认验收的确实是当前源码而不是旧镜像。

截图和临时输出放约定的忽略目录，不包含密钥、真实用户私密对话、出生信息或生产数据。登录、fixture 和本地环境值按本地手册使用，不写入公开文档。

### 8.2 矩阵

共享 UI 或页面布局变更至少覆盖：

- 宽度：320、390、768、1440，以及实际发生换行的临界宽度；
- 主题：light、dark；
- 用户偏好：字号档位、reduced motion；
- 输入：鼠标、仅键盘、触屏等效路径；
- 缩放：200%，必要时结合 `visualViewport`/软键盘；
- 状态：默认、hover/focus、loading、empty、error、disabled、长文本。

### 8.3 走查内容

- 无页面级横向溢出、遮挡、意外布局跳动和不可达操作；
- 弹层不裁切，最上层 Escape/焦点行为正确；
- focus-visible 清晰，主流程无需鼠标；
- 长中文、长英文、空值和极大/极小内容不破坏布局；
- 颜色、圆角、阴影和控件密度仍符合太卜令牌，没有第三方默认皮肤混入；
- 盘面目标、Agent 当前查看内容、导出和分享行为未因 DOM 替换丢失。

自动可访问性工具可以补充扫描，但不能代替键盘、焦点、对比度、缩放和读屏人工检查。未实际执行读屏时，不写“已通过完整读屏验收”。

## 9. 端到端与真实栈

以下情况需要真实栈而不只是离线 fixture：鉴权/Cookie/邮件、DB/RLS、Redis 限流、Worker 租约、跨页面任务恢复、真实流式协议、部署/反向代理和构建产物验证。

- 使用固定测试账号和合成数据，运行前检查活动任务、额度和 fixture 前提。
- 不调用付费真实模型作为默认回归；确需 live 评测时单独确认范围、成本和输出位置。
- 测试产生的数据按契约清理，清理失败要报告，不把残留留给下一次运行。
- 确认栈、镜像、源码和 schema 版本匹配。验收失败时先判断环境前提，再判断代码，不通过反复重跑掩盖问题。

## 10. 回归、不稳定测试与跳过

- 修复 bug 优先添加能在修复前失败的回归；验证它确实能捕获问题。
- 不通过删除断言、放宽到无意义比较、增加任意 sleep 或重试来让测试变绿。
- 不稳定测试先定位竞态、时间、顺序、共享状态和资源问题；不能默认“框架偶发”。
- 必须跳过时注明具体原因、影响、跟踪条件和未覆盖风险；环境不满足与业务不支持分开表述。
- 测试失败时保留真实输出，修复后重跑相关测试和必要的上层验证。

## 11. 完成报告模板

```markdown
## 验证
- `pnpm lint`：通过 / 失败 / 未执行（原因）
- `pnpm typecheck`：通过 / 失败 / 未执行（原因）
- `pnpm test <相关目标>`：通过，<数量或范围>
- `pnpm test:browser`：通过，<相关行为>
- 真实页面：<路由、视口、主题、键盘/缩放>，结果
- 数据库/真实栈：<如适用，环境与结果>

## 未覆盖与风险
- <明确项目；没有则写“无已知未覆盖项”，不要留空>
```

只有实际执行完整命令并得到成功结果时才写 `pnpm verify` 通过。只有离线夹具时写“组件行为通过”，不能写“全站 UI 验收通过”。

## 12. 交付前最终清单

- [ ] 测试覆盖本次修改的公开行为与关键失败路径。
- [ ] 权限、数据、积分/会员等高风险变更有专项回归。
- [ ] 共享 UI 有浏览器行为与真实视觉两层验证。
- [ ] 无真实外部模型、公网或个人数据依赖，fixture 可重复且已清理。
- [ ] lint、类型、测试、build/verify 按范围执行，失败与跳过如实记录。
- [ ] 文档、测试定位器、生成类型和调用方同步，无靠旧实现残留维持的假通过。
