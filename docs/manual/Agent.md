# Agent 使用与实现边界

## 使用方式

在聊天中启用 Agent，由后台 worker 连续执行推理与工具调用。平台模型遵循当前会员、模型权限与积分规则；BYOK 使用用户提供的模型连接，不扣平台模型积分。

Agent 可以调用排盘、命理拓展、知识库、历史对话、受控联网工具，以及管理员或用户接入的外部 MCP 服务。计算和格式化复用 `taibu-core`，方法卡随 Core 维护；支持范围与算法参数见 Core 的 README 和 `ALGORITHM_RULES.md`。

详查工具与八字合盘（`bazi_hepan`）直接引用本会话排过的命盘（`artifact:成果ID`）或用户已存的命盘（如 `bazi_chart:ID`），出生或起卦参数由服务端从成果或记录重建，模型不转抄；没有出生时间的记录只重建年、月、日三柱，不补时柱，也不给时柱推出的命宫、小运等内容。每次执行与缓存重放都重新核对命盘归属。合盘结果在工作区「推演」中把两人八柱排成一条，两盘之间的干支关系画成连线，再按日柱（领以日主互见）、年柱（领以生肖与年命纳音）、其余三组逐条列出，指着一条关系时连线与两端的字亮起；只陈述事实、不打分。

方法卡分体系默认卡、流派卡与技法卡。技法卡在遇到其所述情形时与体系卡同用，不单独作为协作成员的分工。出生时辰未知时按「推理时柱」（`birth-hour`）先推时辰再分析：`bazi_hour_candidates` 列出出生当天各时辰的时柱事实与给定前事年份的引动（交节、子时换日或真太阳时跨日时同一时辰拆开），只陈述事实、不排序；模型据此向用户核对六亲与前事，剩两三个候选时用紫微交叉，经用户确认后才以该候选的出生时分正式排盘，用户答不上来时只排三柱。论断依赖拿不准的取舍（旺衰、格局、时辰交界）时按「验证前事」（`past-events`）先请用户核对两三件往事，再论将来。候选时辰在工作区「推演」中逐个列出。

模型菜单可配置代码模式与计划模式，默认关闭，对下一任务生效。代码模式在沙箱中组合调用受控工具，不能直接调用模型；计划模式允许先研究，提交计划并获用户批准后才可写入长期记忆、归档或派出子分析。计划正文按 Markdown 显示，等待批准时在任务过程中自动展开；批准、修改意见与历次修订都留在工作区的分析计划页。低频工具通过工具搜索按需加载。

浏览器随请求带上所在的 IANA 时区（缺失或无效时按 `Asia/Shanghai`）。普通对话与 Agent 的每条新消息开头写入服务端收到时的「发送时间」（本地时间、星期与 UTC 偏移），任务中途插入、排队和回答问题的消息，以及交给协作成员和后台子分析的任务同样写入；系统提示词不含时间，不随分钟变化，便于模型服务缓存。占当下起卦起局、今天、今年与年龄都以最新一条的发送时间为准。只走人格提示词的一次性分析（如各占术结果页的解读）仍在系统提示词开头写北京时间。

多模型协作通过 `parallel_analysis` 分工后汇总；`background_agent` 提供可并行推进、自动回报并在同一对话中接续的常驻子分析，支持追加任务、停止与解散。成员工具受所选方法卡和体系边界约束。

## 任务状态与恢复

| 状态 | 行为 |
| --- | --- |
| `queued` | 等待 worker 取得租约 |
| `running` | 执行当前 checkpoint 和待处理命令 |
| `awaiting_input` | 等待用户回答，回复后继续 |
| `cancelling` | 已请求停止，等待执行与结算收敛 |
| `completed` / `failed` / `cancelled` | 终态，保留任务与可见历史 |

当前运行引擎为 `pi-durable/1.4.0`。只有匹配当前引擎的 worker 可以接管任务；SQL 定义刷新时，会结束当前引擎无法执行的未完成 checkpoint，并通过既有结算函数处理退款与状态，保留已完成历史和产物。

模型请求走 pi-ai 自带的 Chat Completions 传输（`src/lib/agent/pi-stream.server.ts`）：网关流出的推理（`reasoning_content` 及同类字段）存为思考，并随助手消息一起回传，模型在工具调用之间接着自己的思考往下做，不必每一步从头推理。系统提示要求每批工具调用前先用一句话说明目的。一次回复既没有正文也没有工具调用，或者只说了下一步要做什么却没有调用工具时，会带一段提醒（追加在系统提示末尾）再请求一次，第二次的输出接在同一条回复里；再次没有输出时任务以明确原因失败。思考用完单次输出上限而没有回答时不再重试，直接提示调低思考等级。

模型按管理员在设置中心「AI 服务」里的配置调用：上下文窗口决定压缩阈值；思考只用模型勾选过的等级，未勾选的等级按最接近的一档执行；思考参数格式决定开关和等级写进请求体的哪些字段，普通对话与 Agent 写法一致，自定义参数不能覆盖。来源按列表顺序故障转移，密钥在请求时才解开。

模型请求的所有来源都因过载、限流、网络或 5xx 失败时，任务持久休眠后重试两次（3 秒、6 秒），休眠期间 worker 可以停止或交接。回答失败时，用户在此期间插入的消息会接着开始下一轮回答，不会丢失。某一步连续 5 次让 worker 意外中断（未提交新状态）时，Pi 会停放该步，任务随即以失败结束并提示重新发起，不再无限重试。协作成员的模型按各自的上下文窗口决定压缩阈值。

任务 checkpoint、命令、工具调用收据和事件在 PostgreSQL 持久化。租约与递增 fence 拒绝旧 worker 的迟到写入。相同请求与工具提交重试保持幂等；用户追加、编辑排队消息和回答问题继续复用原任务。

停止请求不会回滚已经完成的外部操作。结算由任务生命周期决定：没有有效回复的失败可补偿，已有可见回复的停止按现有规则保留扣费。平台积分和结算记录在同一事务中处理，BYOK 不走平台积分扣费。

## 权限与凭据

- 用户只能访问自己的任务、对话、知识库和附件。管理员任务日志用于排查运行状态，不授予读取他人聊天正文的权限。
- 模型和工具权限在服务端校验；浏览器字段不能授予系统身份或改变任务所有者。
- 后台执行绑定任务所有者、当前会员状态和有效租约，缺少上下文时失败。
- 待恢复的 BYOK 凭据使用 `AGENT_CREDENTIAL_ENCRYPTION_KEY` 加密保存，终态清除。密钥必须由同一部署的 Web 与 worker 共享。
- 网关密钥由同一把密钥派生的子密钥加密存入数据库，并绑定到所在网关；模型目录缓存里只有密文。更换该密钥后需要重新填写网关密钥。
- 联网请求通过现有安全访问层，禁止访问私网和其他被拒绝的目的地址。

管理员可以在设置中心「功能与激活码 → 功能开关」分别关闭用户功能模块和 Agent 工具范围。模块开关会同时阻止对应的 Agent 排盘、详查和资料读取；Agent 工具范围还可以在不关闭用户页面的情况下收紧八字、知识库、联网/MCP、长期记忆、档案写入、协作和代码模式等能力。工具定义会保留在 Agent 上下文中，服务端在每次调用（包括缓存重放和脚本调用）前重新读取策略，关闭时向 Agent 返回可修正的权限错误。模块状态使用 `feature_disabled:<id>` 保存，Agent 范围使用 `agent_tool_disabled:<scope>` 保存，均由管理员 API 写入 `app_settings`。

管理员可在设置中心的 AI 服务中查看「Agent 任务」，按任务、对话或用户 ID 排查。任务树从持久化日志重建，结束后仍可查看；该接口裁剪聊天正文、工具结果和私有文档，只提供排障需要的运行信息。

## 外部服务（MCP）

管理员在设置中心「Agent 扩展 → MCP 服务」接入平台服务，按会员等级对所有用户开放；用户在「设置 → 扩展 → 连接器」添加只对自己生效的连接器。两者都是 Streamable HTTP 的公开 HTTPS 地址，只在开启联网、且「联网/MCP」工具范围开启的任务中加载。

- 提供方式：`direct` 随每次请求提供；`deferred` 经 `tool_search` 检索后加载；`codemode` 只能在代码模式脚本中调用；`hidden` 不注册工具，只供联网搜索与网页抓取的路由使用。用户连接器只能选前两种，不参与联网路由，每台最多注册 50 个工具（平台服务 200 个）。
- 工具名为 `mcp__<标识>__<工具名>`，非法字符替换为 `_`，超过 64 字符或重名时加短哈希；用户连接器与平台服务同标识时前缀加哈希，跨任务保持不变。
- 每个工具可设置启用、中文标题、检索关键词与「调用前征求用户同意」。需同意的工具调用前向用户提问，拒绝时返回工具错误；代码模式脚本不能调用它们。
- 每次调用前重新读取服务：停用、删除、降档或管理员关闭个人连接器后，进行中的任务下一次调用即被拒绝。一次调用只发送一次，任务中断后不自动重发。
- 服务自带的说明（instructions）只在设置页展示，不进入系统提示；系统提示只列服务名称与管理员或用户写的用途说明。工具描述标明来源，返回内容按外部资料处理，超出字数上限时保留首尾、省略中间，图片只给模型占位。
- 任务开始时连不上的服务被跳过：系统提示只列出其名称，上下文卡显示「未连上」的个数。平台服务的失败记到管理页；用户连接器的原因由用户在连接器页测试连接查看。
- 密钥（请求头或查询参数）以 `AGENT_CREDENTIAL_ENCRYPTION_KEY` 经 HKDF 派生的独立密钥做 AES-256-GCM 加密，附加数据绑定归属、服务与字段名；只写不回显，错误信息与日志先清除密钥原文。更换该主密钥后需重新填写全部 MCP 密钥。连接复用进程级连接池，地址校验与拒绝重定向沿用安全访问层。

「Agent 扩展 → 用户扩展」决定是否允许用户添加连接器与技能、哪些会员可以、每档可加几个（默认连接器 Plus 3 个、Pro 10 个，技能 Free 3、Plus 10、Pro 30 个），保存在 `app_settings` 的 `agent_extensions_policy`。关闭或降档后已添加的保留但不再使用；超出数量时按排序靠前的生效。

服务存于 `agent_mcp_servers`：`owner_id` 为空是平台服务，只有管理员可读写；非空是用户连接器，只有本人可读写。worker 以管理员身份读取全部，但只能写平台服务，他人无法把用户保存的密钥指向别的地址。

## 命盘与保存

工具卡片使用实际返回的结构化产物，复用各占术已有视图。展开、固定或恢复命盘只展示已有结果，不重新排盘或调用模型。数据不完整时降级为规范文本。

桌面可固定到工作区，移动端使用全屏视图。工作区按账号与会话隔离；工具卡片和最终回复中的同一产物按 `artifactId` 去重。

工作区「概览」只列本对话的成果：命盘与推演结果、对话资料，以及计划模式提交的「分析计划」（最新版在最前，修订与批准按时间排开）。读过的资料、提过的问题、写入的记忆与档案不在这里另列一遍——它们的每一步都在聊天里的任务过程中，点开即到对应页面；工具搜索也能按标题找到没打开的页面。「会话详情」的上下文卡按消息、工具、系统提示与压缩缓冲分解用量，「技能」一行列出本任务用过的方法卡（目录随任务注入系统提示，正文由 `load_analysis_method` 读入上下文），点开即到该卡的方法页。

聊天里的任务过程按连续的工具调用、思考与提问分组：每个搜索步骤在行内列出命中的来源与编号，资料、笔记与会话检索列出读到的条目，工具搜索点名加载了哪些工具，子代理调用可展开它当时的参数与返回。思考行默认只显示标题，展开后才显示内容。回答末尾的来源链接只在任务没有搜索步骤时出现，避免与步骤内的来源重复。

任务完成不会自动把命盘或分析保存到用户档案。用户主动保存时，服务端验证任务与产物归属，保存已有计算结果，并保持幂等。长期记忆需要用户开启；归档事件绑定用户提供的事实、所属命盘与来源，编辑或删除时遵循现有来源边界。

## 设置与展示

`/settings` 进入 `/settings/general`。设置导航覆盖常规、账户、订阅、个性化、BYOK、命盘、知识库、连接器、MCP 和帮助；管理员配置入口继续执行服务端管理员检查。

分类切换保留当前工作区的草稿，离开时使用统一草稿保护。切换账号重新挂载面板，隔离上个账号的状态。旧 `#settings/...` 地址通过兼容桥转到页面路由。

浅深主题、字号和减少动画统一使用应用设置与 `src/app/globals.css`。命盘语义配色和普通回复的 Markdown、图表渲染沿用共享组件。

## 开发入口

| 位置 | 职责 |
| --- | --- |
| `src/lib/agent/api.server.ts` | API 用例与权限边界 |
| `src/lib/agent/store.server.ts` | 任务读写 |
| `src/lib/agent/runtime.server.ts`、`durable-storage.server.ts` | Pi 执行与持久化适配 |
| `src/lib/agent/tools.server.ts` | 工具装配与调用 |
| `src/lib/agent/tool-presentation.ts` | 工具结果展示映射 |
| `src/lib/agent/mcp/` | MCP 服务的读写、密钥、连接池、工具注册与设置接口 |
| `src/lib/agent/engine.ts` | 当前引擎版本 |
| `database/functions.sql` | 原子命令、租约、产物和结算函数 |
| `scripts/agent-worker.mjs` | worker 启动入口 |

本地启动使用 `pnpm local:update`；状态和日志使用 `pnpm local:status` / `pnpm local:logs`。平台配置以 `.env.example` 为准。修改运行或计费流程需执行对应单测、`pnpm test:db` 和浏览器验收；发布前执行 `pnpm verify`。
