# 数据、数据库与安全规范

本文定义 PostgreSQL/RLS、身份上下文、密钥、私有文件、生产数据与备份的强制边界。任何“只是内部工具”“只是测试”的例外都不能绕过用户数据隔离。

## 1. 数据安全基线

1. **默认拒绝**：缺少身份、权限或资源归属时失败，不返回部分私有数据，也不回退系统主体。
2. **最小权限**：连接角色、函数、API、Worker 和页面只获得完成任务所需权限。
3. **服务端强制隔离**：RLS、事务和资源归属是主防线；客户端过滤和隐藏入口只是展示。
4. **最小暴露**：查询、响应、日志、错误、缓存、分享和截图只包含必要字段。
5. **可恢复**：结构变更、删除、备份和恢复都要验证，不能只证明命令曾经执行成功。

## 2. 数据库文件与事实来源

`database/` 是当前定义的唯一事实来源：

| 文件/区域 | 职责 |
| --- | --- |
| `schema.sql` | 新库的表、列与约束定义，不是任意已有库的自动升级脚本 |
| `functions.sql` | 函数与视图当前定义 |
| `triggers.sql` | 触发器 |
| `access.sql` | 角色、授权、RLS 与策略 |
| `indexes.sql` | 索引 |
| `seed.sql` | 系统主体和必要数据不变量 |

项目不维护编号迁移和版本账本。`db:init` 对声明对象与 PostgreSQL 反解文本做差异处理，但不能用它替代已有业务表的明确升级，也不能通过删表重建规避迁移。

### 结构变更流程

1. 说明业务需求、受影响角色/函数/索引/RLS 和旧数据范围。
2. 先检索当前表、约束、原子函数、生成类型和调用方，避免新增平行字段或重复规则。
3. 对已有库先备份，编写明确、可审查的 ALTER/约束/回填 SQL；在隔离库验证升级和回滚边界。
4. 同步 `database/` 当前定义与生成类型，不手改生成文件。
5. 评估回填期间的锁、默认值、NOT NULL、唯一性、外键、索引和失败重跑行为。
6. 执行 `db:diff`、`test:db` 及相关路由/并发测试；发布按自托管手册另行授权。

禁止为了“让新代码工作”直接修改生产结构，禁止在没有备份和恢复验证时删除或重建业务表。

## 3. ScopedDb 与身份上下文

- Web/Worker 数据访问通过 `src/lib/db/context.server.ts` 的 `userDb()`、`anonDb()`、`systemDb()`，只有 DB 层持有 pg/Kysely 和连接池。
- 每个受控事务显式设置有效角色、`request.jwt.claims` 和 statement timeout；事务本地设置不得跨连接泄漏。
- 用户 id 必须来自已验证会话或受控任务主体，不能信任请求 body 中的用户 id。
- `systemDb()` 只用于白名单系统路径。普通业务请求缺少身份时必须失败，禁止 `user ?? system`、`anon ?? system` 之类回退。
- Better Auth 使用独立 identity 连接和 schema；业务模块不能借身份连接绕过业务 RLS。
- 一个操作需要跨用户/系统写入时，使用明确的领域用例与权限检查，不在任意路由直接提升权限。

## 4. RLS 与权限策略评审

新增表、视图、函数或改变查询路径时，必须回答：

- 表是否启用 RLS？anon、authenticated、系统主体分别能做什么？
- SELECT/INSERT/UPDATE/DELETE 是否分别限制，WITH CHECK 是否覆盖新行？
- 通过 id、外键、分享令牌或对话关联的资源，是否可能串联出他人数据？
- 聚合、计数、搜索、向量检索和错误差异是否泄露“不可见资源存在”？
- 函数是 invoker 还是 definer？definer 是否确有必要并固定 `search_path`、校验主体、限制 EXECUTE？
- 视图、物化结果、数据库函数是否绕过原表策略？
- 管理员和系统主体是否有独立明确路径，而不是所有请求共用高权限角色？

权限测试至少覆盖：本人成功、他人资源失败、匿名失败、管理员/系统按契约成功或失败。不能只测试 UI 不显示按钮。

## 5. 事务、约束与并发

- 数据完整性优先由主外键、唯一、CHECK 和事务保证，不能只依赖应用先行判断。
- 多表写入、积分账本、会员状态、任务命令和产物保存按业务不变量放在同一原子边界。
- 唯一约束与幂等键需对应真实业务重复，而不是只锁客户端请求 id。
- 并发测试覆盖双击、重试、两个 Worker、任务取消与完成竞争、余额不足和重复回调。
- 事务内不执行远程网络、模型或邮件调用；锁持有时间保持有界。
- 超时和死锁作为可能的正常故障处理，调用方不得无界自动重试。
- 数据排序、分页和游标需要稳定键，避免并发写入导致重复/遗漏。

## 6. 密钥与环境变量

- `.env.example` 只列变量名和安全示例，真实密钥不得提交；本地生成密钥、API key、数据库口令和测试凭据同样属于秘密。
- 服务端密钥只能在明确 server-only 模块读取；客户端只允许 `NEXT_PUBLIC_*` 和 `NODE_ENV`。
- 不以 base64、加密后前端可解密、拆分字符串或写入常量作为“隐藏密钥”。
- 日志、错误、测试快照、PR、文档、截图和模型提示中不输出真实密钥。
- 密钥按环境隔离并限制权限；轮换时更新引用和部署配置，旧密钥按流程失效。
- BYOK 等用户密钥使用现有加密存库与解密边界，只在调用所需最小范围出现，不回传给普通页面或日志。
- 依赖安装、脚本和示例配置不得把环境变量打印到终端或 CI 日志。

怀疑泄露时优先吊销/轮换和评估影响，不只是从 Git 最新提交删除。

## 7. 文件、附件与文档处理

- 上传使用 `readUploadedFile`/现有流式边界，限制真实字节、数量和 multipart envelope，不能先完整读入再检查大小。
- 文件类型不能只信扩展名或客户端 MIME；按功能验证必要内容并限制解析复杂度。
- 存储 key、下载 id 和分享令牌不是授权本身；读取前验证所有者、引用关系或公开分享权限。
- 私有文件不暴露真实磁盘路径，不使用用户输入拼接路径；防止路径穿越、覆盖和符号链接逃逸。
- 文档解析在受控 worker 线程中执行，限制大小、页数/耗时与内存，异常文件要可失败收尾。
- 图片、PDF、Excel、Word 等解析器及其输出均按不可信输入处理，不执行文件内脚本或宏。
- 删除业务记录时按引用关系回收附件；公开分享撤销后，旧 URL/令牌不能继续绕过权限。
- 备份、导出和调试副本同样属于私有数据，具有访问控制和保留期限。

## 8. 缓存、队列与搜索数据

- 用户私有缓存 key 包含身份/权限范围，账号切换时清理或隔离，不把 A 用户的 Query/Redis 结果发给 B 用户。
- Redis、BullMQ、向量索引、全文搜索和本地浏览器缓存不是权限真空；它们保存的数据与源数据具有相同敏感性。
- 队列 payload 最小化，重试和死信不得无限保留敏感正文。
- 删除/修改源数据时同步失效派生索引和缓存；无法立即同步时明确一致性与访问边界。
- 分享、公开社区和知识库发布前明确数据范围，不能因为内容进入检索索引就变成公开。

## 9. 生产数据与运维操作

- 生产数据默认只读。排查优先使用日志、聚合指标和脱敏最小查询，不导出整表或复制到个人环境。
- 写入、删除、结构升级、发布、回滚和备份恢复均需要明确授权与操作范围，不能把一次授权扩展到其他环境。
- 本地/隔离验证使用独立项目、数据库和卷；不得重建共享镜像或让测试指向生产。
- 测试夹具清理优先走应用契约，避免直接 SQL 留下关联残留；必须直接处理数据时先在隔离环境验证事务。
- 不把真实用户对话、出生信息、命盘、档案、记忆、邮箱或文件作为公开测试 fixture。
- 操作完成后核对实际环境、对象数量和结果，不能只依赖命令退出码或容器名称。

## 10. 备份、恢复与删除

- 备份必须加密/限制访问，保留策略与数据敏感级别一致；密钥和备份不能只有同一故障域的一份。
- 定期执行恢复验证，检查 schema、角色/RLS、行数/关键不变量、文件引用和应用可用性；只有 dump 文件不代表可恢复。
- 结构变更前记录回滚是“反向 SQL”“恢复备份”还是“前滚修复”，不要默认所有变更都能无损失回滚。
- 用户删除、会话撤销、分享撤销和缓存失效按产品契约完成；不能仅删除页面入口。
- 调试快照和临时导出用完删除，不长期放在仓库、`tmp`、下载目录或公开对象存储。

## 11. 安全评审清单

### 数据与权限

- [ ] ScopedDb/RLS 覆盖所有读写路径，无缺失身份回退系统主体。
- [ ] 本人、他人、匿名、管理员/系统和并发路径均有测试。
- [ ] 函数、视图、触发器、索引、授权和旧数据影响已评审。

### 秘密与内容

- [ ] 客户端、日志、响应、截图和文档没有密钥或多余私有数据。
- [ ] 文件大小、类型、路径、归属、解析和回收边界完整。
- [ ] 缓存、队列、搜索和分享没有绕过源数据权限。

### 运维与恢复

- [ ] 生产操作已明确授权，结构与删除有备份和恢复/前滚方案。
- [ ] 当前 SQL、生成类型、测试和文档同步。
- [ ] 临时数据、夹具和访问权限有清理结果。
